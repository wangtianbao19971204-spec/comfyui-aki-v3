# 迁移登记约定

`index.json` 的第 1 版是当前三库的结构基线，不是一次给在线数据库执行的升级。`schema_version` 是原插件自身的表，与此目录的 `baseline_version` 不是一个版本体系；禁止直接用 `PRAGMA user_version` 或写入原表来冒充迁移完成。

未来数据库变更在唯一主仓库提交，新增 `0002_<purpose>/`、`0003_<purpose>/` 等目录；不得重写已发布的 `0001` 文件。每项变更至少包含：

1. 适用的库、最低来源版本、原表/索引/触发器指纹。
2. 有序 SQL/代码、数据保留策略、批量大小、失败恢复方式。
3. 虚构 fixture 和经过授权的一致备份上验收；保留 ID、正文、个人字段与来源绑定。
4. integrity_check、行数/身份守恒、触发器/索引检查和失败中断测试。
5. 迁移前一致备份、升级回执、可恢复的回退方案及上线条件。

当前工具只接受已实现的第 1 版，并对未知版本失败关闭。它不提供在线升级、自动降级、删表或覆盖真实数据库的命令。需要第 2 版业务时，应连同专项迁移执行器、版本门禁和测试一起实现；不要仅修改 index 数字。生产启用依然需要单独部署授权。
