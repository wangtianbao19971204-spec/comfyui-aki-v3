# 归属写库的两个坑（2026-09-19 实测）

## 坑 1：`workbench_tag_meta` 上的触发器会**重建**成员表

`prompt_selector/tag_library.py::_prepare_members` 里注册了三个触发器：

```sql
AFTER INSERT/UPDATE/DELETE ON workbench_tag_meta BEGIN
  DELETE FROM workbench_tag_folder_members WHERE tag_uuid = NEW.tag_uuid;
  INSERT OR IGNORE INTO workbench_tag_folder_members
    SELECT NEW.tag_uuid, value
    FROM json_each(json_extract(NEW.data, '$.folder_ids'));
END
```

也就是说：**`meta.folder_ids` 是唯一真源，成员表只是它的派生索引。**

后果：**任何**对 meta 的写入（写回脚本、UI 里收藏一个 tag、编辑归类…）都会先把该 tag 的
成员行全删掉，再只按 `folder_ids`（只有叶子，没有区域）重建。
于是「叶子 → 补上所属区域 uuid」的祖先闭合行会被冲掉。

### 症状

写回后跑断言会看到 `闭合违规 62652/248217`，而 `folder_ids` 里其实都是对的。

### 处理

写回**之后**必须再跑一次全局闭合：

```powershell
python G:\ComfyUI-aki-v3\benchmark_reports\2026-09-17_krea2_nl_import\fix_closure.py --apply
```

输出应形如：

```
闭合检查 248,217 对；缺口 62,652
已补 62,652 行
复查：检查 248,217 对；缺口 0
成员总数 448,984；重复 0
```

> 判据：`fix_closure.py` 复查缺口为 0、重复为 0，才算这次写库收尾干净。

## 坑 2：归属快照里的 `text` 是截断的

`全库_面与主题_*.jsonl` 每行的 `text` 只留了 150 字，而库里很多条目是整条提示词
（上千字）。**拿快照做正则匹配会漏掉一大截命中**：同一套规则，用截断文本算出
动作›姿态 12,028，用 `tag_tags.text` 全文算出 19,272。

所以重算归属时必须回到库里取全文：

```python
full_text = {u: t for u, t in con.execute("select t_uuid, text from tag_tags")}
```

## 坑 3（已查清，结论更正）：那 103,239 行**不是**漂移

先前我把「成员表 − folder_ids」当成脏数据，**结论是错的**。

成员表是「**原生位置 ∪ UI 归属**」的并集索引，不是 `folder_ids` 的镜像：

| 位置 | 含义 |
| --- | --- |
| `tag_tags.subgroup_id`（INTEGER，指向 `tag_subgroups.id_index`） | tag 的**原生位置**（导入时的来源叶子） |
| `meta.folder_ids` | UI 维护的**归属目录** |
| `workbench_tag_folder_members` | 两者并集，目录筛选查这张表 |

抽查 12 条，多出来的行恰好都是「原生叶子 + 它的区域」：

```
tag: 'haunter,pokemon,no humans,pokemon (creature),ghost'
  原生位置     : 服饰、人设杂项/人设 / 非原创人物
  folder_ids  : 人外种族/西幻魔物 | 各式场景/场景 / 战斗华丽
  多出来的行   : 【区域】服饰、人设杂项 | 服饰、人设杂项/人设 / 非原创人物
```

统计吻合：64,529 个 tag 的 folder_ids 非空，多出来的叶子行 64,496 ≈ 每个 tag 一条原生叶子。

**所以不要清理**（`prune_members_extras.py` 保留但别用，我先前那句建议作废）。
完整排查方法见：
`G:\ComfyUI-aki-v3\benchmark_reports\2026-09-17_krea2_nl_import\成员表排查方法_20260919.md`

> 顺带记录两个类型坑：`tag_tags.subgroup_id` 是 INTEGER 的 id_index 不是 uuid；
> `tag_subgroups` 的元组下标顺序是 `(id_index, group_id, name, ...)`，别把 name 当 group_id。
