# 下一阶段交互验收流程

版本 1.1 · 编制日期 2026年9月30日 · 状态为执行中；逐项实际结果见 `benchmark_reports/2026-09-30_next_workbench/acceptance_progress.md`。

配套范围、分批安排与目标行为见[下一阶段界面与提示词改进计划](G:/ComfyUI-aki-v3/production_tools/下一阶段界面与提示词改进计划.md)。本文件给出测试准备、操作步骤、明确的通过条件和证据口径。以下是用例定义，已执行与未执行的状态以执行记录为准；历史通过记录只用来确定基线，不自动转为本轮通过。

## 一 执行与记录规则

每个用例保存：编号、所属批次、候选版本、实际入口、工作流及分支、数据样本ID、初始状态、操作、预期值、实际值、状态、证据路径、问题编号和恢复结果。同一用例在多个入口执行时分别记录子结果，例如 `X03/角色/a1/正向/追加`。

状态只使用“未执行、执行中、通过、失败、受阻、不适用”。不适用需要能力清单和原因；功能坏了不能记为不适用。一个编号下全部适用子结果完成，才能给该编号整体结论。没有可用工具测量的指标写“受阻或未测”，不拿其他指标替代。

严重度：P0为误写、丢资料、错误提交分支或无法恢复；P1为核心操作失败、输入错误、主要操作不可达或性能硬门槛不达标；P2为非阻断视觉或文案问题。P0和P1未清零不得发布对应批次。P2也要明确处理或列入交付限制，不能省略。

实际点击使用浏览器真实指针、标准键盘或可访问性接口。合成 `.click()` 未触发处理器、定位器超时或自动化失联，不能单独判为产品故障；同一方法失败两次后记录并换有依据的方法。截图证明显示，节点回读证明写入，服务日志或队列回执证明执行，三者各自保存。

所有写入测试使用隔离工作流和候选资料库。资料编辑、删除、收藏、备注、最近使用都可能写库，不能因为只修改测试节点就认为生产资料无变化。测试环境没有隔离好之前，只允许读操作。故障注入在候选接口或测试适配层执行，不破坏生产磁盘权限、不让生产服务崩溃。

## 二 测试环境和固定样本

### 2.1 环境登记

记录浏览器及版本、操作系统、屏幕与页面缩放、视口、硬件、ComfyUI前后端版本、统一插件文件哈希、启动配置、资料版本及数量。记录测试期间有无生图、模型下载、其他重负载标签页和开发工具。

功能主矩阵使用视口1440×1000、1000×900、700×900，页面缩放100%，三主题以及常用控制台和完整工作台。实际半屏容器宽度单独记录；窄屏若按设计转单列可通过，不能只看浏览器总宽度。另在1440×1000检查125%和150%缩放。

工作流基线取当前UAP v2的独立副本。a1、a29、k2和ext04至ext09共九分支均做只读目标和任务能力登记。正式工作流文件及用户当前打开页不用于故障写入。执行后恢复原工作流、主题、缩放及临时面板状态。

### 2.2 数据样本

| 样本集 | 固定内容 | 用途 |
|---|---|---|
| 小样36条 | 六种资料类型各6条：正常、长正文、无图、图片加载失败、同名异身份、可编辑或只读边界；一条可覆盖多个特征 | 卡片、详情、保存、来源定位、正文保真 |
| 查询30条 | 六类型各4条，加6个跨类型或边界查询；记录查询、筛选、预期ID及排序约束 | 搜索质量和前后比较 |
| 原生词库193条 | 中性内容，分布在至少3个分类，包含跨分类同名条目；全部具有固定测试名称前缀，以同一全局查询恰好命中193条 | 明确验证80→160→193，以及最后33条 |
| 性能3000条 | 固定结构和正文长度分布，固定缩略图尺寸与本地素材；不全部使用空正文 | 首屏、检索、分批显示和资源增长 |
| 当前完整库 | 登记真实数量和修订，仅做只读测试或使用一致性候选副本 | 验证大库行为，不能用3000条外推全部资料量 |
| 文本链样本 | 普通文本、拼接、权重、正负向、手写、LoRA触发词、Embedding、随机、未知节点、多编码器 | 预览支持边界及目标保护 |

所有预期输出在候选修改前写入固定样本清单。UI测试使用中性内容，如 `blue sky`、`red coat`、`standing`、`soft light`。不得截取用户敏感资料作为公开演示样例。

精确文本基准：T0为字符串 `blue sky,\nsoft light`，其中 `\n`表示一个实际LF换行；N0为 `low quality, blurry`。选择资料A=`red coat`、B=`standing`、C=`soft light`。除用例另述外，目标初始值为T0，负向为N0，权重为1。整段替换A后的期望是严格的 `red coat`；追加末尾沿现有写入器规则，必须预先列出完整期望字符串，禁止用与生产代码相同的函数计算测试答案。

### 2.3 证据等级

| 标记 | 证据内容 | 不能替代什么 |
|---|---|---|
| M | 单元或模块检查，明确夹具和输入输出 | 不能替代真实窗口、点击和视觉结果 |
| A | 接口响应、保存版本、服务资源哈希、队列状态 | 不能证明按钮能被用户点到 |
| B | 真实浏览器操作，截图或短录屏，焦点和字段回读 | 无实际任务时不能证明生图成功 |
| J | 真实任务ID、提交快照、成功或失败回执、输出检查 | 不能证明未执行过的模型组合兼容 |
| F | 浏览器或系统性能采样、原始数据、统计方法 | DOM数不能冒充内存，后端耗时不能冒充端到端延迟 |

## 五 提示词预览和写入用例

| 编号 | 操作步骤 | 通过条件与证据 |
|---|---|---|
| P01 | 向独立目标放入T0、N0，打开本次写入预览但不应用 | 当前字段逐字符一致；无节点、资料、队列写入；标题不会误称实际编码器输入。B+A |
| P02 | 在共享待用合成规则支持的测试链加入A、B、C，调序为B/A/C，A权重1.5，C停用；预览追加末尾 | 待用合成区严格为 `standing, (red coat:1.5)`；完整写入预览为 `blue sky,\nsoft light, standing, (red coat:1.5)`，其中反斜线n代表实际LF；C保留但不输出；源资料不变。M+B |
| P03 | 将A改为临时正文，再移除B、恢复C；另创建正向和负向项并切换方向 | 预览与启用顺序一致；临时编辑有标记；负向不能被无提示写入正向；混合内容要求拆分。M+B |
| P04 | 分别输入权重0、1、1.5、3、负数、3.1、空值和无穷值 | 0至3按既有语法处理；无效值拒绝并保留原值；停用与0不混淆；未支持的模型语法说明准确。M+B |
| P05 | 对支持的固定链分别使用文本、拼接、换行、画师和权重样例 | 预览与独立预期文本严格相等；列出具体分支、节点和方向；不是只核对字符数。M+B |
| P06 | 切换随机模板、未知脚本节点、外部优化、运行时反推或动态LoRA触发词 | 不执行这些节点取预览；不能确认的部分显示原因和定位；不输出猜测的最终文本。M+B+A |
| P07 | 使用两个编码器或精修输入，再进入透明素材、二倍及四倍分支 | 分别显示各文本来源；无提示词分支说明不使用；不会沿用上一分支的“已确认”状态。B |
| P08 | 对A执行追加末尾、有效光标插入、替换有效选区及整段替换 | 各操作与事先写出的完整期望相等；整段替换先预览；方向、其他字段和资料原文不变。M+B |
| P09 | 完成一次写入→撤销；另一次写入后手工追加新文本→再撤销 | 第一次逐字符恢复T0；第二次拒绝覆盖新文本并解释；不能仍显示撤销成功。M+B |
| P10 | 展示替换预览后分别改目标正文、删除节点、重载图、改节点身份、改变连线、禁用分支 | 每个子情况旧应用均被拒绝，实际目标写入次数0；重新选择后才可操作。M+B |
| P11 | 加入资料A后从另一候选窗口更新A，再点应用；同时保留另一项临时编辑 | 首次应用提醒源已更新并刷新预览；临时编辑不丢；用户重新检查后再应用；不悄悄替换正文。M+B+A |
| P12 | 在资料读取或预览进行中修改待用顺序、方向或目标，再让旧结果返回 | 旧版本不覆盖新预览、不写入；当前目标与预览版本一致；关闭后无迟到写入。M+B |
| P13 | 快速双击应用；待应用完成后模拟最近使用记录保存失败 | 单次在途操作只写一次；写入成功和记录失败分别报告；重试记录不再次插入正文。M+B+A |
| P14 | 切工作流、刷新页面、关闭后重开，检查来源定位和撤销状态 | 草稿可按保存契约恢复；旧目标和撤销失效；手写或改写部分不伪称仍与源资料完全一致。B |

## 七 资料卡和ATG用例

以下C01至C09对六资料类型中适用的能力分别记录；ATG至少单列一个真实身份样本。仅有图片、只读资料等的操作按B03能力表判断。

| 编号 | 操作步骤 | 通过条件与证据 |
|---|---|---|
| C01 | 查看六类型正常卡片、长名称、长正文、空正文和缺操作项 | 名称、类型、方向或用途清晰；无null、undefined和空按钮；不可用动作有合理处理。B |
| C02 | 点击卡面复制、收藏、加入待用及详情，逐次回读目标 | 动作互不串联；复制是完整原文；加入待用有反馈；目标仍为T0。B+剪贴板或等效回读 |
| C03 | 在候选浏览器拒绝剪贴板访问后复制 | 不报虚假成功；完整正文展开且可选择；恢复权限后可再次复制。M+B |
| C04 | 打开ATG或字符串详情→编辑→仅修改测试正文→保存→重开 | 进入正确Tag编辑器；只改对应ID；来源和收藏备注保留；其他同名项不变。B+A |
| C05 | 分别查看无绑定图片、有效图片、请求失败图片，并点击重试 | 三种状态可区分；只有加载失败提供相应重试；不把占位图当验证样图。B+A |
| C06 | 打开长正文与原图→返回列表，再从详情回到已筛选页 | 正文无截断丢失；滚动、筛选和可用页码恢复；返回后的目标未变。B |
| C07 | 两个候选窗口打开同一可编辑项，先保存窗口一，再保存旧窗口二 | 旧版本被拒绝或先比较冲突；窗口二草稿保留；不静默覆盖新版本。A+B |
| C08 | 保存测试资料时模拟断网、接口错误，再恢复并重试；另执行取消 | 失败不显示已保存；草稿保留；重试只产生一次预期修改；取消无写入。M+A+B |
| C09 | 查看提示词方案和仅图片情绪版；修改“本次正文”后重开原资料 | 方案正负段按方向使用；无文字时无虚假插入；本次编辑不污染全局模板。A+B |

## 十三 性能测量程序

### 13.1 样本和统计

基线和候选使用同一浏览器、设备、视口、资料修订及相同空队列状态。主性能档为1440×1000、夜间主题、100%缩放；另用700×900复核主要卡顿和布局。界面性能测量期间不生图。

热操作先预热5次，这5次不计入；随后记录30次独立操作。冷打开定义为关闭旧测试页，使用明确记录的浏览器HTTP缓存条件与同样的存储快照，在新页面首次进入对应面板；至少10次，报告全部原始值和最大值，小样本P95按排序后第ceil(0.95×n)项计算，不把它描述为高精度分位估计。服务器是否热缓存单独记，不把新标签页称为整机冷启动。

热操作P50和P95均按同一最近秩方法计算；30个样本的P95取升序第29个。每项同时记录成功率、失败次数和最长一次。超时样本保留为失败并记录等待上限，不能从统计中删除。搜索防抖包含在端到端耗时内；接口等待、界面构建和图片加载额外分解。

M0只测已有能力。现有待用列表的编辑、调序及合成可作为对应基线；新停用动作和新编码前检查只在候选版测绝对预算，不虚构修改前耗时。F08仅对同功能、同起止的操作计算前后差异。

优先用浏览器性能轨迹和事件时间记录。CPU采样注明浏览器渲染进程、整个浏览器还是后端进程；基线和候选范围必须相同。若不能取得可靠CPU或堆数据，标记未测；不能以响应更快推出CPU或显存更省。
