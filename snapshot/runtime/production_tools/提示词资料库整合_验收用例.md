## 1. 执行约定

### 1.1 环境与恢复

- S3–S6 使用候选库、隔离的浏览器状态与可恢复工作流副本。共享源码或插件启动会自动迁移数据时，先改用安全可配置的候选环境，不能以测试为理由启动未知写入器指向生产库。
- 不提交图片生成、不加载 GPU 模型、不下载模型或词典，不修改范围外插件业务。模型用例优先用已有资源只读引用和隔离元数据测试；合成身份不伪装成真实可用模型。
- 每项交互记录初始目标、原文、选择、分支、模式和资料修订；完成后撤销临时应用或恢复副本。故障注入使用候选 I/O 模拟，不制造生产磁盘满、权限破坏或后端崩溃。
- 数据库检查校验逻辑字段与记录，不要求 SQLite 备份文件字节相同。正文保真使用原始字段逐字节/Unicode 值对照，不用归一化哈希掩盖变化。
- 不适用必须写明该入口本来不提供何种能力及证据；缺陷导致功能消失不能标不适用。未运行、被阻断、结果未知分别记录。

### 1.2 结果记录格式

每项结果至少包含：`case_id、适用对象、阶段、候选版本、源版本、环境、初始值、步骤、期望、实际值、状态、证据路径、问题编号、恢复结果`。

允许状态：未执行、执行中、通过、失败、阻断、不适用。不要填“基本通过”。一项在多个入口重复执行时分别保存子结果，例如 `F01/a1/shared/positive`；顶层只有全部适用子结果通过才能通过。

风险等级：P0为数据损失/错误写入/恢复失败；P1为核心功能、分类、输入冲突及统一/精简硬门槛；P2为非阻断显示或体验。P0/P1全部通过方可发布；P2记录是否达到约定目标和遗留影响。

### 1.3 小样资料集

真实小样 40–60 条，由 S1 实际数据分层选取，覆盖全部来源和字段；合成例仅补齐缺少的冲突/错误场景。保存固定样本清单，不每次换容易通过的样本。

| 样例组 | 内容与目的 |
|---|---|
| FX01 普通词与别名 | 同正文不同中文名；同中文名不同正文；同词在两个类别，用于身份和检索 |
| FX02 特殊语法 | `(soft light:1.2)`、不同权重、Unicode、转义括号、多行、`BREAK`；实际支持的随机/占位符原文 |
| FX03 模板与片段 | 服装局部片段、含服装但描述整个场景的长模板、正向片段、负向预设 |
| FX04 用户引用 | 收藏、别名、最近使用、预览存在/缺失、自定义角色与官方同名不同作品 |
| FX05 模型关联 | 两模型共享词、同名异目录、空词、多短语与分组、手写同词、用户覆盖、推断词 |
| FX06 Embedding | 同名异目录、带下划线/空格/括号、缺失资源、权重上下文，使用实际支持语法 |
| FX07 版本冲突 | 两窗口改同条、旧版本全量保存、删除后热缓存、迁移期间新增、发布后新增 |
| FX08 失败输入 | 空记录、无 ID/重复 ID、未知字段、无效分类、断链预览、模拟写入失败/中断 |

合成文本使用独立测试名称；测试完成不留在生产库。不得对用户全文运行删除重复词的正则来“制造通过结果”。

## 10. 覆盖策略与判定

所有 D/C 机械检查覆盖相关候选全量，语义审查按完整计划的全审与抽样约定。F/R 的目标隔离、正负向和保存重开覆盖 A1/A29/K2 的全部适用入口；不存在的能力说明不适用。键盘用例按实际输入上下文执行，不机械展开无意义笛卡尔积。

优先覆盖高风险组合：共享库与 [03A] 对同目标应用；Anima 同名角色与共享资料；手写文本与 LoRA 自动词；custom-scripts 与 LM 的 Embedding；旧弹窗与分支切换；全量保存与单条编辑并发。

通过率同时给出“通过/适用总数”和“未执行/失败/阻断/不适用”，并附子用例分母。S6 不能拿已运行的一小部分作为100%分母；所有应执行 P0/P1 均通过才可进入发布。S7 只做关键回归和增量保护，不在活跃用户资料上再次全量故障注入。

上述要求保持 V2.1 基线。当前执行状态以[验收台账](G:/ComfyUI-aki-v3/benchmark_reports/2026-09-07_prompt_library_integration/acceptance_results.json)为准；未登记足够范围证据的用例不得记为通过。

V2.1验收对应：D04/C01/C03检验资料归一与逻辑标准；F04/F05/F09/U04检验动作一致；A10检验检索一致；U01/U03检验入口、概念及操作精简。不可只用“功能都还能打开”替代这些目标。
