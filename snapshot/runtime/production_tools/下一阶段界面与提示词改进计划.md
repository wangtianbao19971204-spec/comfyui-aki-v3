## 二 范围清单与共同规则

### 2.1 三套清单分别验收

| 清单 | 具体成员 | 必须检查的内容 |
|---|---|---|
| 六种资料类型 | 提示词片段、基础Tag、Anima画师、Krea2情绪版、画师串、提示词方案 | 搜索、来源、卡片、正文、详情、复制及适用的编辑和写入 |
| 六类选择器 | 角色、服装、姿势、背景、画师、画风或质量 | 选择、翻页、当前目标、追加、替换、撤销、键盘和恢复 |
| WeiLin 原生词库 | 原生分类列表、全局搜索、收藏、编辑、分页、批量操作 | 必须通过原生词库弹窗验收，不能用统一资料库替代 |

ATG 是本计划要覆盖的卡片和编辑入口，按实际条目类型登记，不额外虚构为第七种资料类型。每个入口登记“读取哪里、编辑哪里、写入哪里”；同名资料使用稳定身份区分。

### 2.2 每一次写入遵循同一规则

1. 浏览、复制、收藏、选择、加入待用都不修改提示词目标。只有明确的应用动作写入。
2. 可写状态显示当前工作流、分支、节点与字段名称、正负方向。窄面板允许折行，不能把全部目标信息藏在悬停提示里。
3. 方向未知、目标不存在、分支未启用、字段已连线或身份过期时，显示具体原因；资料仍可浏览和复制。
4. 普通追加沿用现有操作，不增加重复确认。整段替换必须展示替换前后，并在确认时再校验目标和原文。
5. 写入完成以回读目标值确认。正文已写入但最近使用记录保存失败时，分别反馈，不能引导用户再次插入。
6. 撤销只还原最近一次有效写入。目标之后被手动编辑、工作流切换或身份失效时，拒绝覆盖新内容。
7. 不自动改写英文Tag，不静默删除重复或冲突词。可提供提示和定位，修改由明确动作完成。

### 2.3 状态与保存范围

| 状态 | 本计划要求 | 刷新或跨工作流时的边界 |
|---|---|---|
| 浏览位置、筛选和当前页 | 同一入口往返恢复；筛选变化回第一页 | 仅恢复可用分类和有效页码，不恢复失效查询对象 |
| 已选资料 | 同次打开的选择器跨页、搜索和详情返回保留；清搜索不清选择 | 关闭或取消结束本次选择任务，未应用的临时勾选清除；再次打开不恢复这些勾选，原节点值及其正常回显不变；已加入待用的项继续保留 |
| 待用列表 | 沿用现有会话草稿，保留顺序、临时编辑、权重；新增停用状态也保存 | 恢复正文后重新确认当前目标；图库等动态来源必须重新关联，不能恢复过期函数引用 |
| 提示词优化草稿 | 保留现有同页、同工作流、同分支的内存恢复 | 刷新仍可能丢失，界面应说明；本阶段不暗增永久保存全部草稿 |
| 收藏、备注、自建资料 | 明确保存后可重开、刷新核对 | 写回原资料维护者；失败保留草稿，不产生伪成功 |
| 工作流参数 | 同步节点；使用现有保存工作流操作落盘 | 关闭面板不等于保存工作流，文案保持明确 |
| 新增生产配置和结果快照 | 用户明确保存后持久化 | 不保存API密钥；恢复前比较差异，不自动加载模型或提交任务 |

## 四 提示词预览的具体设计

### 4.1 分清三种文本

| 显示层次 | 含义及展示要求 | 能够确认什么 |
|---|---|---|
| 本次写入预览 | 当前目标原文，加上选中的资料、顺序、权重和本次操作；显示完整正向或负向结果 | 能与应用后的目标字段逐字符比较 |
| 编码前文本检查 | 只沿当前活动分支中明确支持的文本来源、拼接和格式规则解析；每个编码器输入单独展示 | 能确认受支持静态链的文本；不能代表全部节点运行结果 |
| 本次运行确认 | 如现有节点的执行输出能够提供实际文本，则绑定任务ID、分支、编码器与实际文本记录 | 能确认这一任务、这一编码器的运行文本；不能推定其他任务相同 |

首批必须交付第一层和第二层的明确支持表。第三层依赖现有节点是否暴露实际输出；未暴露的列为M3能力缺口，不修改核心执行器来追踪所有节点。遇到随机词、脚本、外部优化、运行时图片反推、自定义未知节点，显示“包含运行后才能确定的内容”并定位该节点。禁止执行未知节点来取得预览。

已经核实的差异需要进入支持表：UAP当前读取的是字段原文；WeiLin执行时还可能合并上游文本、选择随机模板、处理LoRA标记并加入触发词；Anima会合成分段和转换画师格式，已有部分提示词元数据输出。首批复用可独立调用的纯文本规则；不能为了预览调用整颗编码节点、加载LoRA或占用GPU。已有元数据也要核对记录位置及含义后，才可标为本次编码输入。

预览不调用节点执行函数、不排队、不加载模型或分词器、不请求外部优化。Anima现有执行元数据只覆盖相应节点写出的正向内容，必须核对任务身份和节点ID；不能从该记录外推负向、全部Anima节点、多编码器或Krea2的实际文本。

“最终提示词”只有在对应文本来源已经完整确认时才可使用。多个编码器、精修分支或多段文本分别列出，不能压成一段并假称是全部输入。无提示词的透明素材、超分分支显示“不使用提示词”。字符数可以准确展示；未接入对应分词器时不显示虚假的精确Token数。

### 4.2 用户操作顺序

1. 从当前分支打开预览，顶部显示目标和检查状态，默认展开当前方向；另一方向有独立入口。
2. 从资料库或选择器选用资料。待用列表仍是现有列表，允许调序、临时编辑、权重和正负向拆分；增加“本次启用”开关。
3. 预览随有意义的修改更新。来源行显示原资料名及定位入口，临时改动标注“本次已编辑”；手写内容标为手动编辑，不反向猜测来源。
4. 明确选择追加、光标插入、替换选区或整段替换。只展示当前入口实际支持的操作。
5. 应用前核对草稿版本、原资料修订、目标身份及目标原文。任一变化使旧预览失效，先更新预览，再由用户重新应用。
6. 应用后回读节点并显示结果，可撤销。刷新或切换工作流不恢复旧撤销权限。

权重范围继续使用现有0至3。权重0和停用是不同操作，不擅自替换彼此。Anima、Krea2的格式能力由实际节点定义；不支持的权重方式保留原文并说明，不能通过表面包一层括号假称兼容。

验收重点：P01至P14、X03至X06、E01、E02。首批将支持节点、未知节点和本次测试过的分支逐项列出。

## 五 搜索和资料卡的具体设计

### 5.1 搜索规则

保持现有本地搜索与索引，先核对当前排序，再按固定样本细化。统一界面必须区分“跨来源搜索”和“当前列表搜索”，显示生效的资料类型、用途和筛选条件。搜索不到时先提供清除筛选，避免把筛选后的空结果描述成资料不存在。

拟定相关性顺序如下；这是目标规则，不宣称所有来源当前已一致：

1. 名称、规范Tag、已登记别名的完整精确匹配。
2. 名称、规范Tag、已登记别名的前缀匹配。
3. 名称、Tag或别名包含查询内容。
4. 正文包含查询内容。
5. 来源或分类包含查询内容。

同档才使用收藏、已有使用记录和稳定身份排序；收藏不能挤掉更准确的命中。默认不新增收集行为日志。使用次数与最近使用数据不存在时，按稳定身份排序，不能伪造热度。跨来源保持分组及各组真实数量，不把各接口第一页拼起来宣称为全库全局排序。

三条实际路径分别处理：共享提示词库已有相关性排序，重点拆分名称与正文命中并显示原因；Tag及ATG相关入口当前有独立包含查询和时间排序，应在分页前增加查询相关性，无查询时保留原顺序；WeiLin原生词库仍有自己的前端筛选，需明确同步规则及范围，不能假定改共享接口就同时生效。各来源的排序结果按资料修订稳定分页。

Tag字段可在查询比较时等价处理空格和下划线，原文与写入文本保持不变。大小写、中文别名、多词查询的当前行为在M0固定；首批不新增模糊纠错、语义模型或高级查询语言。每张搜索卡可显示一条简短命中原因，如“名称精确匹配”“中文别名”“正文命中”。

质量样本固定为30条中性查询：六种资料类型各4条，另加同名异源、别名冲突、Tag空格下划线、筛选空结果、长正文、混合输入各1条。查询附预期ID或期望排名约束；资料确有对应项时，精确匹配必须进入对应来源组首位，同档并列用固定规则。绝不靠临时更换样本提高通过率。

### 5.2 卡片及 ATG 操作

卡面依次保留名称、类型或用途、可用预览、正文摘要和常用动作。复制、收藏、加入待用独立点击，不连带打开详情或写入。详情承载完整正文、来源、资料身份、适用模型和编辑入口；未确认的模型适配明确标注。

ATG和字符串资料编辑继续进入对应Tag编辑器。六种资料类型按各自能力显示操作：方案的正负段不能混成一个方向；仅有图片的情绪版不能伪造可插入正文；只读基础资料不能给出无效保存按钮。

保存必须保留来源、收藏、备注等未编辑字段。版本冲突保留用户草稿并要求重新读取比较；不能让旧弹窗覆盖新保存。无图片与图片加载失败使用不同提示；后者有重试，前者仍可阅读和复制。缺图不通过生成全库封面来解决。

验收重点：S01至S10、C01至C09、D01至D04。

## 六 选择器与 WeiLin 的具体设计

六选择器保留各自用途、筛选及原生节点适配，统一共同动作与反馈。当前页选择和待用列表分别显示数量；选择卡片不立即写入。跨页保留本次选择，返回时恢复已选标记。新增接入优先复用现有稳定资料身份，无法定位来源的项不得伪装成可跨会话恢复的资料。

同一来源、稳定ID和方案分段重复加入待用时，拒绝重复添加并提示“这条资料已在待用列表”；保留原项的顺序、临时编辑、拆分和权重。不同来源同名项保持独立，方案正负段也分别保留。

固定键盘约定：Tab进入控件；卡片区域方向键移动焦点；Home和End移动到本页首末可操作卡；卡片区域的Enter或空格只切换该卡临时选中，不直接应用到目标；按钮上的Enter按该按钮含义执行；文本输入及中文组词期间不触发卡片快捷键。Escape按顺序处理：输入法组词时交给输入法；存在内层详情或编辑弹窗时只关闭该层；否则焦点在有内容的搜索框时清空搜索并保留面板；其余情况关闭当前选择器或工作台这一层。编辑草稿有未保存内容时先执行离开保护，不直接丢弃；一次Escape只处理一次，不向底层传播。

WeiLin原生弹窗维持首屏80、每次最多追加80。全选按钮称为“全选已显示”，只选按下时已经显示的条目；随后加载的新条目默认不选中，数量实时准确。相同查询和筛选的重绘保留已展开数，改变查询或筛选回到首批80。编辑、收藏始终作用于搜索结果的真实源分类及稳定条目身份。

不为统一外观强迫所有选择器使用相同页大小。角色和画师现有60、服装和姿势现有48作为基线；背景及画风质量以M0登记为准。只有实测说明有必要时才调整。首批不引入全新的通用虚拟列表框架。

验收重点：W01至W07；X01至X07在六种选择器分别执行。

## 八 风格与低资源标准

### 8.1 风格标准

沿用现有白天、夜间、多色三主题，共享颜色、字号、边框、间距、圆角、焦点及按钮规范。新增组件优先使用现有样式变量，确有缺口才补共享变量。

主要动作、普通动作、危险操作和禁用状态有固定层级；每块区域只突出一个当前主要动作。卡片的复制、收藏、选中状态各有可辨识反馈，图标按钮提供名称。正文保留阅读与复制能力；长标题换行或可展开，不能遮挡按钮。

主按钮目标高度建议不小于32像素，纯图标点击区域建议不小于28像素；普通文字对比度至少4.5比1，控件边界及焦点至少3比1。状态不能仅靠颜色区分。动画以已有简短过渡为准，新增动画不超过150毫秒，遵守减少动态效果设置，不恢复大面积实时模糊或常驻装饰动画。

### 8.2 拟定性能门槛

以下数字是后续验收预算，尚未实测达到。M0锁定同机、同浏览器、相同数据和空队列条件。若基线已超预算，记录为待优化问题；不得事后调宽标准并称已达标。P95表示95%的样本不慢于该值。

| 指标 | 目标与起止定义 |
|---|---|
| 点击反馈与文字输入 | 事件开始到首次可见反馈，P95不超过100毫秒；不包含等待数据返回 |
| 已加载资料的写入预览 | 最后一次有效修改到完整预览可见，32项且合计不超过10000字符，P95不超过150毫秒 |
| 面板热打开 | 指针打开到首批控件和卡片可操作，P95不超过400毫秒 |
| 面板冷打开 | 同页面首次打开、相关缓存条件已记录，到首批内容可操作，P95不超过1500毫秒；图片完整加载另报 |
| 本地搜索 | 最后一次确认输入到最终首屏可操作，包含防抖时间，P95不超过800毫秒；同时单报请求和渲染时间 |
| 已加载数据翻页或显示更多 | 点击到新增内容可操作，P95不超过300毫秒；需要接口请求时总预算800毫秒 |
| 长任务 | 热操作的单次主线程阻塞超过200毫秒即列问题；超过50毫秒的次数和总时长与基线比较 |
| 隐藏或关闭 | 事件处理完、在途请求归零后5分钟内，本插件额外图扫描和无变化DOM写入为0；关闭对象无遗留定时器或观察器 |
| 回归上限 | 已有热操作P95不比基线增加超过max(基线的10%,20毫秒)，且仍须满足对应绝对预算 |
| 资源增长 | 30次开关和30分钟混合操作后不出现随轮数持续增长的泄漏；按配套流程复测，不能只比较两个瞬时内存值 |

首屏只构建当前页，图片按需加载。缓存以资料修订和筛选为边界，有容量上限并在离开时释放不必要对象。不新增大型依赖、全库常驻副本、持续全图遍历或全库图片预取。若未来需要后端排序改动，单列该批重启与接口验收，不能沿用前端修改“无需重启”的结论。
