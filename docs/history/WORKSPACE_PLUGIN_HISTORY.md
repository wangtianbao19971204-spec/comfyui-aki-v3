# 插件与训练依赖的本地完整历史

这轮补齐 24 个上游插件仓与 SD-Trainer 的**全部本地已存提交图**，包括不再由普通分支指向的 reflog 提交。它不重复前一轮 Core、Workbench、旧主仓历史迁移，也不从网络补取远端版本。

各镜像的精确入口、提交数量、旧 SHA 保留/重写数、标签、外置载荷、扫描统计及映射文件 SHA-256 见 `workspace-plugin-public-inventory.json`。清单确认的是隔离镜像准备完成；是否已经接入主仓、原 `.git` 是否已私有归档，以主仓最终验收和祖先检查为准。

## 文件与可信边界

- `<component>-public-map.json`：每个原提交到公开提交的完整映射、原 refs、reflog 补迁 tips、标签映射、签名例外和移除内容的记录。
- `<component>-archive-receipt.json`：空树聚合入口，覆盖本组件所有历史 tips；不代表可直接运行的插件版本。
- `<component>-public-verified.json`：当前权威逐提交验收，`verifier_contract: 2`。早期 `public-verify`、`public-final-verify`、`public-hardened-verify` 阶段记录已移入仓外审计档案，可按移动收据恢复，不替代此最终复验。
- 源与公开对象的完整安全扫描报告留在本地维护证据目录；公开库存只引用通过结果和计数，不复制匹配原值、原始私有 Git 或环境配置。

作者、提交者、时间、编码、消息及本地可用父提交的顺序保持不变。没有改动树或父关系的提交保持原 SHA。树/父发生变化时，后代 SHA 也会改变；原提交签名不能继续验证，因此移除失效签名头并逐项记录。原签名与原对象保存在仓外私有 Git 档案中。

## 为什么部分历史树不同

公开仓不保存权重、数据库二进制、私密配置、缓存目录、超限文件及未能安全检查的压缩载荷。相关原始 blob 不写入公开对象库，不采用改成 `.txt` 等假后缀的方式保留原字节。历史树移除这些叶子，并增加 `.comfyui-history-references.json`，记录原路径、原 Git object ID、SHA-256、大小和原因。

历史 gitlink 也不保留为 `160000` 模式；引用文件记录其依赖路径和精确提交，不伪造未下载的依赖源码。正常源码、许可证和限额以内的代码文档图片继续保留。当前实际源码与未提交的本地改动由主仓源码导入流程另外维护，不能用历史 HEAD 的文件去复活现场已经删除的文件。

外置按原 blob 身份保守执行：同一受禁 blob 的其他文件名别名也改为 reference。Manager 曾在缓存目录引用公共的零字节 blob，因此其历史中的同空 blob 安全别名也一并记录，而不是声称这些旧树仍可执行重建。这个空 blob 在其他组件的合法空文件中仍可存在；“原 blob 在整套主仓必须不存在”只适用于确定的凭证载荷，不能套用到普通共享空内容或依赖文件。各隔离镜像的排除记录与主仓全局凭证禁止列表是不同边界。

AlekPet 的 ACE 语法高亮库中，79 个精确对象的 `token` 字段实际为语法 scope。它们经过独立逐匹配审查，以精确内容 SHA-256、路径及指定两种 literal 规则登记，不设置目录级豁免。另有三个历史配置对象和一个包含配置的 ZIP 载荷不能作为占位凭证放行，已外置；旧 example 文件不能仅因叫 example 就豁免。主仓的安全示例由当前源码导入流程提供，不恢复这些旧鉴权值。

SD-Trainer 原件是浅仓，仅有一个本地提交且两个父提交不在本地。公开版本省去这两条缺失边，记录原父 SHA 与顺序；它是明确标记边界的非浅镜像，不能被描述为远端训练项目全部历史。

## 验收和导入

`scripts/workspace_history.py` 只写新隔离镜像，不修改原工作树、原 refs/index、主仓 refs/index 或持久 Git 配置。所有 Git 子进程清理继承的 `GIT_*` 重定向，禁用 replace objects、系统/全局配置、hooks 和 fsmonitor；需要的 `safe.directory` 仅在命令/进程内生效。

验证覆盖全部本地提交与 annotated tags，逐字节核对消息/元数据、父顺序、树变化、外置记录的原始大小/哈希、直接 tree/blob refs 和 tag targets，并核对 refs 精确集合、符号目标和 HEAD。即使旧/新 tree SHA 相同，也遍历检查 gitlink 与禁止载荷，不把相同 SHA 当作免检依据。每个镜像再通过严格全历史凭证/资源门禁与 `git fsck --full --strict`。

没有分片文件/快照 manifest 的独立对象可分区并行调用同一安全扫描器，规则与所有历史路径别名保持完整；含分片/manifest 的集合自动回退原串行跨片检查。不能用 `content-only` 模式替代公开门禁。检测器仍是启发式检查，不能声称数学上证明没有任何密钥。

主仓维护者只从清单给出的已验证本地镜像导入 `refs/heads/history-archive`，原标签放入清单的 `legacy/workspace/<component>/` 命名空间。若清单列出无普通 tag 引用的 annotated tag 或直接非提交 refs，也需逐项保留。接入应保留主仓当前树，不 checkout 历史插件树覆盖当前项目；完成后验证每个聚合入口均为主仓祖先，再处理临时 import refs。最终主仓、bundle 和 GitHub 推送仍要做独立的全历史安全验收。
