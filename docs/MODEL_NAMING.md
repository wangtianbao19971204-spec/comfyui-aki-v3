## 分类

保留 ComfyUI 加载器的目录边界，在其中按“家族／用途”整理：

```text
ComfyUI/models/
├─ loras/
│  ├─ anima/<用途>/<规范文件名>
│  ├─ anima-2.9b/<用途>/<规范文件名>
│  └─ krea2/<用途>/<规范文件名>
├─ diffusion_models/
│  ├─ anima/图像生成/<规范文件名>
│  ├─ anima-2.9b/图像生成/<规范文件名>
│  ├─ krea2/图像生成/<规范文件名>
│  └─ qwen-image-2.1/图像生成/<规范文件名>
└─ checkpoints/
   ├─ anima/图像生成/<规范文件名>
   └─ sam3.1/目标检测与分割/<规范文件名>
```

LoRA 用途统一为：画风与画师、角色与人物、服装与配饰、姿势与动作、背景与场景、光影与色彩、概念与效果、细节与修复、滑块与调节、控制与编辑、自训角色、其他与待核。普通角色、画风和自训成品各自保留原身份。用途优先使用已审查的组织记录与既有分类；网站宽泛标签不自动覆盖具体用途。原版 Anima 与 2.9B 分开，来源显示通用 Anima 时结合确切版本、已审查家族及原 2.9B 目录判断，不能凭跨家族标题推断兼容。

底模指图像生成权重，SAM 是工具。编码器、VAE、检测器、插件固定权重和目录型模型仍按各加载器的配套契约放置，不能为了目录外观拆散配置、词表或分片。KJNodes 内置 intrinsic LoRA 的固定文件名由插件拥有，不套用用户 LoRA 的磁盘改名规则；其来源和用途继续登记。

## 文件名

格式：`家族__公开模型名__确切版本__精度__cv版本ID__f文件ID.后缀`。

只保留有可靠记录的字段。没有语义版本就省略，不补造 v1；无 Civitai 身份时用固定上游提交 `rev...` 或实际完整摘要的前 12 位 `sha...` 区分。显示名保留原公开名称，磁盘名称作 Unicode 标准化、非法字符替换和长度收敛。来源页、上游原文件名、版本／文件 ID 与完整摘要另存于来源目录，名称截短不丢失原身份。

同版本的 BF16、FP8-Mixed、INT8、INT8-ConvRot 分别保留；同名、同摘要也不自动合并删除。四个自训成品保留角色、形态、r32、原 v1 与摘要身份，训练正式 release 目录继续作为原始发布记录，不随运行模型改名。

工作台的显示名称采用 `【家族｜用途】公开模型名 · 版本 · 精度`。触发词、个人备注、收藏、排除、用量和来源元数据不因改名而改变。

本次全量扫描另为 3 个原隐藏项补出可核验的 AutoV3 指纹，并为原无侧车的 Qwen GGUF 建立默认元数据及规范显示字段；其默认侧车摘要仍为 pending。306 个权重的完整实测 SHA 单独登记在来源目录和验收收据，不依赖这些缓存声明。

LoRA Manager 的常规与排除缓存须同时核验：本轮 286 个用户 LoRA 包括 283 个常规项和 3 个排除项，排除项仍保留原排除状态。迁移后发现 3 项排除缓存保留旧显示名，已通过本机 scanner 的 `full_rebuild=true` 从现行 sidecar 重建索引。磁盘与常规列表已更新不等于排除缓存也已同步；两类缓存中的现行路径、文件名、显示名、个人字段和 loader 枚举需分别核对，刷新后再验收。缓存原件及修复前后记录留在仓外，不进 Git。加载列表或管理页可见只证明路径和索引，不能声称全部界面交互或 GPU 推理通过。

## 换机器与维护

下载时仍按来源目录的确切上游文件选择，再放到 `current_path`；不要把规范名当成网站上的下载文件名。权重、预览和真实 sidecar 留在 Git 外。完整权重摘要用于确认取得同一文件，不能用 sidecar 的声明代替。

[命名规则](../scripts/model_naming_rules.py)只生成白名单分类信息；[迁移工具](../scripts/standardize_models.py)使用已部署 LoRA Manager 的本地接口维护共享身份、预览和 recipe，并精确更新保存工作流的路径。额外 sidecar 与旧 WeiLin 本地图片引用也要迁移。下载声明中的原文件名／URL、训练历史和原 inventory 保留。运行区私有训练 profile 与独立 Qwen API 工作流只更新现存模型路径，原件保存在仓外。

在主仓用已经核验的 Python 依次执行（示例目录必须换成新的仓外位置）：

```powershell
& $comfyPython -X utf8 -B scripts\standardize_models.py plan --runtime '<运行根>' --evidence '<全新仓外收据目录>'
# 核对候选、来源、完整摘要与额外配套，再绑定刚输出的摘要：
& $comfyPython -X utf8 -B scripts\standardize_models.py review-plan --evidence '<同一收据目录>' --plan-sha256 '<plan的实际SHA256>'
& $comfyPython -X utf8 -B scripts\standardize_models.py stage --evidence '<同一收据目录>' --plan-sha256 '<review-plan输出的新SHA256>'
# 此时只改主仓；先审查并验证工作流、参数和相关源码，再 seal。
& $comfyPython -X utf8 -B scripts\standardize_models.py apply --evidence '<同一收据目录>' --plan-sha256 '<已审查plan的SHA256>'
& $comfyPython -X utf8 -B scripts\standardize_models.py verify --evidence '<同一收据目录>'
```

`apply` 是明确的运行区变更，只能用于已获授权的范围；不重启、清队列、下载或生图。队列非空会停止；链接路径、目标重名、内容漂移、个人字段变化、配套遗漏或共享同步待恢复均拒绝继续。中断后保留日志并逐项核对实际状态，不能盲目重跑。默认计划不移动模型，`stage` 只修改主 Git；部署之前必须完成相应验证。

回退依赖原／新路径对应表和精确日志：在空队列中把同一权重及配套反向移动，恢复本次字段与引用；不覆盖后续用户资料或用旧数据库替换在线库。权重改名不复制或删除权重，私有备份保存原 sidecar、源码／配置和 SQLite 一致副本。本次清理掉的评估权重不在回退材料里。

完成后更新来源目录、MD、manifest 的对应 metadata 项、当前工作流摘要与技术记录；核对 loader 列表、全部文件和内容摘要，以及 4 个自训 release 副本。刷新已打开的工作台／工作流页面使其使用新下拉项；已经打开但未保存的旧图不会被磁盘迁移自动改写，需重新打开相应更新后的保存文件。
