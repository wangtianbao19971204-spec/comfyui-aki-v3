# 提示词分类完整规则

版本：2026-10-03.9。适用：资源库、基础 Tag 库，以及读取这些资料的 UAP、统一工作台、WeiLin 和六类选择器。

本册把 9 月 20 日起的分类标准、多日全量扫描与分批修正、9 月 27 日集中验收、后续来源修订合同和 10 月 3 日试审口径合并为当前审核规范。目标是让同类问题按同一规则处理，减少重复全文送模和重复争论。**本文是审核与后续实现的规范；本次没有修改生产分类引擎或批量写回分类。**

规则由主册、逐类准入边界表、注册目录和历史索引共同组成：本册的判定与边界、[注册分类及匹配词目录](分类规则注册目录.md)、[历史补充规则与发布索引](分类规则历史补充索引.md)。匹配词目录只生成候选，不能绕过本册的语义、否定、对象和来源限制。旧《分类标准.md》《分类标准变更记录.md》及所有冻结账本继续保留。

### 判定优先级

1. **保护对象和原始证据**：正式原文、ID、来源、图片绑定、个人备注、收藏、资格、工作流和用户确认结果不可被推断覆盖。
2. **确认库和 schema**：先决定是在资源库的主题／小主题／细分，还是 Tag 的 themes／facets 下判断。
3. **明确证据与正负范围**：先解析正负段、权重、角色段、专名和句法对象，再判断分类。
4. **有效的新修正覆盖旧的同范围口径**：需有明确 amendment 或已验收的对应发布；日期晚但未发布的草稿不能覆盖正式结果。不同库、父级与叶级、词面与记录修正不能相互覆盖。
5. **完整事实优先于局部命中**：实际人物、实体、场景、媒介和修饰对象优先；独立正向证据不能被同文反例连带删除。
6. **注册表定义优先于 ID 字面猜测**：先查中文名称、规范父级及已有别名，不能自行缩窄稳定 ID。
7. **无法确定时保留明确上位或标记未定**：不强行分类、不为降低未定数量选择一个猜测结果。

### Tag 当前路径与六类选择器

Tag 的 29 个 themes、6 个 facets 在注册目录逐项列出。这是已有结构的快照，不是每条旧归属都正确的证明。`角色›原作` 不能容纳无依据的作者；`画风›画质` 不能成为所有画师、风格和未知专名的兜底。

| 选择入口 | 可使用的有据内容 | 不能反推 |
| --- | --- | --- |
| 角色 | 作品／原创／身份／种族等适用资料 | 入口里的每条都属于某一具体职业、人数或装束 |
| 服装 | 服饰实体、配饰、材质剪裁与状态 | 服装名直接证明角色身份或场景 |
| 姿势 | 人物姿态与明确动作 | 动态光效、物体运动等于人物运动 |
| 背景 | 实景空间、地貌、建筑、背景表现 | 来源或图案里的场景就是实际背景 |
| 画师 | 有来源可核对的作者及正向组合 | 所有账号或名字都是作者 |
| 画风质量 | 媒介、风格、画质和细节各有依据的资料 | 选择器合并入口意味着数据库语义合并 |

以上是审核映射边界，不是本次新增前端筛选或自动跨库转换。独立节点入口与统一工作台应读取相同已验收数据。

## 十二 减少模型消耗的执行流程

本节为本次制定的工作约束 C，不承诺尚未实测的节省比例或额度报价。后续先用规则完成可确定项，模型只处理无法按已有证据决定的部分。

1. **先判是否有变化**：数据、schema、规则版本、来源哈希全相同，复用已验收结果；有具体新问题才重开对应范围。
2. **廉价结构检查先行**：ID／父子闭合、重复路径、非法节点、正负字段混用、过期来源绑定由确定性程序发现。输出候选，程序命中不等于语义已确认。
3. **按规则家族聚类**：专名拆词、修饰对象、否定范围、父叶缺口等各成一组；抽取能区分条件的正例、反例、保留例，先定规则，避免对同一问题重复写长解释。
4. **按完整输入缓存**：至少以库、完整正文和正负段、schema、相关来源身份／上下文、规则版本组成缓存键。应用到另一记录前仍验证当前分类、资格和用户确认状态。
5. **只把必要材料送模**：单个样本的完整正文、现有分类、有关规则段、适用注册节点、必要来源证据。不要每包重复传整段聊天、全部 514 节点或整个历史账本。
6. **合并同正文的语义阅读**：相同输入可共用语义判断，个人字段和修改操作逐条校验；归一后近似不能直接当相同。统计区分阅读全文次数与记录覆盖数。
7. **简单问题用短结论**：规则 ID、原文证据、动作、边界即可；专名身份、跨主体长文、互相冲突的历史标准才升级复核。
8. **限制复核范围**：实际删除、主类迁移、规则变更影响和争议项优先二审；已验收相同输入不每轮全量双审。修复影响所需门禁仍必须完成。
9. **固定一个生产修改负责人**：默认串行整理；可用一个限定范围子代理作历史检索／独立审阅，避免多个高强度长上下文代理重复读取同一库。禁止子代理再递归展开审核队伍。
10. **设置批次结束点**：本阶段规则册交付后结束。下阶段仅依据具体高频规则缺口启动小批验证，不自动重开 21 万行逐条审计或重新跑 1000 条试审。
11. **记录实际用量**：分别记模型、输入／缓存／输出 token、重试与复核数、墙钟时长；共享账户百分比不当作本任务精确扣费。无实际账单不声称精确消费。
12. **避免无限争论**：补一次必要证据仍不能判断就留下具体 unresolved 和所需证据；不为了清零反复发送相同原文。

## 十三 修改与验收门禁

### 分类结构和粒度

- 当前暂停新增叶子和第四层；优先修复已有节点误挂、同义重复和漏召回。
- 历史默认显示门槛为全局至少 10 个不同 ID，每个默认可见叶有至少 3 个已读有效正例。它是显示实现条件，不是新建节点的充分理由。
- 少于 30、30–99 的数量段用于检查粒度，不是自动删节点门槛。不为凑数扩大定义；不以隐藏节点冒充语义修复。
- 单叶净减至少 10 且至少 30% 需绑定当前源码／索引哈希的专项说明、正反例和复核；低于该线仍不得丢失有效正例。
- 节点合并须先证明同义，保留稳定 ID 迁移与取消筛选路径；不同概念不能为了计数合并。

### 各类工作需要哪些验收

| 变更类型 | 必做验证 | 不能声称 |
| --- | --- | --- |
| 仅规则文档整理 | 出处与状态、编号唯一、注册关系、覆盖冲突、链接存在、正式数据／源码守卫 | 生产算法已按全文规范实现、分类已全部修好 |
| 精确记录分类修正 | ID、全文／before 哈希、最小差量、非目标不变、父叶闭合、对应历史与索引／查询 | 清单外记录也被审完 |
| 通用规则修改 | 正反例与保留例、确定性全库影响测量、实际影响审核、历史回放、申报差量、完整索引及上线验证 | 只有单元测试或扫描归零就已交付 |
| 来源更新 | 固定版本 raw 差量、旧 Tag 修订、个人数据与图片绑定、SQLite／索引／来源门禁 | 只查新 ID 就“全站同步完成” |
| 影响 UI 或选择器语义 | 真实 DOM／浏览器对应流程、served SHA、候选计数、选择与取消、独立入口 | 静态源码或合成事件等于真实浏览器／物理输入法验收 |

### 发布顺序

冻结数据、源码、规则及原文证据 → 明确问题与预期 → 正反例和实际影响 → 审核影响 → 隔离暂存 → 非目标字段、完整索引、历史、查询和差量门禁 → 回退准备 → 核对唯一 owner／空队列／生产基线 → 受控发布 → 线上验收 → 更新收据。

- 纯细分规则变更若声明不改父类／主题，其计数必须零漂移；需要父归属改动时必须单独申报事务，不把旧“零变化”门禁绕开或误用为永不准补父。
- 修改规则后旧 hash-bound 扫描与门禁失效，必须按新源码重测；不改扫描器口径美化分类修复结果。
- SQLite 服务连接未关闭时不替换数据库；不停止他人服务或非空生成队列；正常发布失败按整组备份恢复并记 rolled_back。
- 运行版本、磁盘版本、served 资源和在线数据分别验证。记录当前实际 PID、创建时间、启动参数和健康基线，不复制历史 71 节点／旧 PID 作为新门槛。
- 浏览和搜索不触发自动重分类；规则缓存失效是受控过程，不能新增后台轮询或全量画师正文加载。
- 状态只用 proposal／staged／preflight_passed／accepted／rolled_back 等真实阶段。文档已完成与生产已交付分别记录。

## 十五 边界判定补充（2026-10-03.2）

本节范围为 C：把已核实 schema、历史定义及复审裁决编成审核合同，不宣称生产分类器已经实现。与前文同一库、同一字段、同一范围发生表述歧义时按本节具体条件解释；限定发布 B 的适用记录和例外仍保留。旧账本不覆盖；新的具体改判必须追加绑定原值的 amendment。

### 先判断哪一种“不确定”

| 动作结论 | 必须满足的条件 | 后续处理 |
| --- | --- | --- |
| supported 支持 | 目标已注册；完整原文或可核来源直接满足准入；例外及父子依赖已核；拟改字段确有差异 | 只是有据提案，另过落库合同、影响和发布门 |
| rejected 驳回 | 已知准入规则与完整证据可以判定该提案不成立，例如对象错误、仅局部属性、已有独立正例反对删除 | 驳回本动作；不推断画面中绝对不存在该物，也不自动执行相反动作 |
| optional 可选 | 语义确实成立，但只是已覆盖的冗余元数据一致化或合理主次偏好 | 不计错挂/漏挂；无须为降低候选量直接改库 |
| unresolved 未定 | 类别准入未明确、来源缺失、指代歧义、证据冲突，或写入合同未确定，因而不能裁定具体动作 | 写明缺失证据/合同，保持原数据；禁止用可选掩盖不确定 |
| safety_hold 保护 | 原有受保护状态或本次有明确保护依据 | 中性记录适用范围；不新增敏感细分，不等于全文语义通过 |

“某个理由不能支持新增”与“现有分类必然应删除”是两项不同断言。新增和删除共享相同证据标准；删除必须另查完整正文、来源与独立正例，不能从驳回一个理由直接反向推导。

| CTG-08 | shading须先消歧为最终图像制作中的明暗塑形；宽技法不强求已命名具体子法 | 正向shading在明确同作用域drawing/illustration/render制作语境，或明文说明绘制明暗或计算表面色彩/明暗表现形体，可入Tag画面›技法；detailed/expert不独立作证也不抹去已确认的绘制含义 | 裸shading无制作语境或主体层级不明未定；实体遮光/受光变暗、色调shade、元数据和仅画中画排除该依据；不猜cel/hatching等叶，不自动补打光/质量；正负/冲突/保护仍先行 | C窄准入；固定版Shading词义+既有宽父/作用域守卫；Tag路由为本规范选择，非来源原有分类 |

1. **词义依据与本地路由分开。** 固定版本定义把 shading 描述为绘图/渲染中改变明暗以表现形体/深度。该词义不自行决定本库归属；本节将已消歧的图像制作过程纳入既有宽技法核心，标为C规范选择。
2. **两种充分表达。** A：正文直接说明通过绘制明暗或计算表面色彩/明暗来表现形体；B：明确同一最终图像的drawing/illustration/render制作语境中，正向使用shading绘制名词。上下文可以分布在同一无局部限制的提示段，但不能借别的对象、负向媒介、元数据或来源目录补齐。仅知道字段是图像提示词不等于已满足制作语境。
3. **评价与事实分开。** detailed/expert是评价性修饰，不独立推出制作方法；若B已满足，它们也不取消shading本身。best illustration / 8k render只能帮助确认正文制作语境，不能单独成为技法正例。不要求猜出cel shading、cross hatching或任何新增叶。
4. **主画面是层级。** 明确最终插画脸部采用shading可成立，效果无需覆盖每个像素；只有墙上画/屏幕图像内的shading而无独立最终画面正例，不成立主画面技法。衣物或脸部shading究竟是受光、图案还是制作处理不明时未定。
5. **词面不足与未定。** tree shading a person、a shaded face from a lamp、shades of blue、软件说明中的shading字段，不据该词补技法。裸shading没有可确认的制作语境时未定，不从目录/作者/世界知识补场景；不能据此反向删已有归属。
6. **原守卫保持。** 负权shading不作正例；同对象冲突不能拆词绕过；整条保护与共同版本依赖优先。按RUN-08逐证据汇总，独立film grain等正例不被未定shading遮蔽，shading成立也不解锁纯风格分支。
