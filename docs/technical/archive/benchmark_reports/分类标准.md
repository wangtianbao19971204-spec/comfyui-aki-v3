# 分类归属标准

## 当前执行入口 2026年10月3日

现行审核规范见[分类规则总册](分类规则总册.md)，配套[完整注册目录](分类规则注册目录.md)与[历史补充索引](分类规则历史补充索引.md)。本文件以下内容保留为原标准及历史追加；新旧覆盖关系按总册第九节执行。本次仅整理文档，未更新生产引擎或写回试审提案。


文档版本：2026-09-24.55。覆盖 2026-09-20 晚至 2026-09-24 的分类治理、三级细分、交互及连续抽检修正。

后续修改分类，先读本文件，再读《分类标准变更记录.md》和最近一批发布报告。修改现行口径时，同步更新这三处，不只留在聊天里。历史样本、旧账本和旧报告保留，不覆盖为新结论。

## 1. 总原则

**以 tags 原文及完整正文的表达核心决定归属；少兜底、少误挂，不靠猜测凑分类，不靠拆碎类别凑覆盖率。**

- 主主题表达这条内容的核心。辅助主题可以多选，但每项都要有正文证据。不能因为开头出现 `1girl`、画师、质量词或年份就覆盖真正的服装、动作、角色或场景核心。
- 同一条记录可同时表达外观、服装、动作、镜头等不同语义轴。它不是只能放进一个文件夹。
- 证据不足时保留明确的上位主题，或保留有理由的未定；不把相近词硬塞入错误类别。
- 综合场景必须确有多主题场景内容。长文本、模板、占位符、多视图或 `char1` 本身不证明它是综合场景，综合场景数量也不能直接称作“兜底率”。
- 分类修改只改有依据的分类字段；原始 tags、正文、别名、ID、来源、图片、收藏、资格和模型绑定等非目标字段保留。

## 2. 当前结构与数字口径

结构为 **大主题 → 小主题 → 细分主题**，例如：外观与身体 → 头发与发型 → 双马尾。

截至第二十九批正式发布及接口核验：15 个大主题、89 个实际使用且达到默认显示门槛的小主题、500 个默认可见细分。分类注册表共 93 个小主题；其中“内容排除、质量排除、叙事与情境、连续场景”当前没有进入该内容池。**93 是注册容量，89 是当前池中小主题数，不能混用。**

完整小主题、细分 ID、父级、原文匹配词与当前计数见《分类主题目录.md》。人数是独立筛选面，不强行塞进小主题列表。计数是版本快照，每次发布后重算。

15 个大主题：角色与身份、人物数量、外观与身体、服装与配饰、动作与姿势、表情与视线、背景与环境、构图与镜头、光影与色彩、风格与媒介、画师与作者、质量与细节、物品与道具、综合场景、负向与排除。

### 筛选面与来源分开

- 用户所说的“面”明确指人物数量等筛选面。人物数量作为大主题入口，与内容主题组合使用。
- 人数只取正文明确标记；不从标题、别名、镜像、多视图、分镜数或 `solo focus` 猜人数。
- 来源目录、导入批次、模型、SFW/NSFW、热门/冷门、自然语言/原子 tag、模板、用途和选取资格各保留自己的轴，不冒充内容小主题。
- 作品和角色专名归角色身份；画师专名或画师组合归画师与作者；具体风格和媒介归风格与媒介。专名不拆成普通词，也不按角色常识补正文未写的服装、职业、种族或场景。

## 3. 原文证据怎么判

1. 阅读完整正文，先分清正向描述、否定/排除、负向提示词区、引用文字、作品专名及实际描绘对象。
2. 明确正向的完整 tag 可触发其已有规范概念；自然语言须判断主语、修饰对象、动作关系和上下文，不能见词就收。
3. 同义词、大小写、下划线/空格、已验证的连字符写法可以归到同一稳定节点；这是匹配层归一化，不改写用户原文。
4. 负权、零权、明确负向用途与负向提示词部分，不产生正向数量或细分命中。新增解析写法必须同时验证正例与排除例。
5. 较窄细分必须有足够窄的证据。泛“袜子”不直接推出短袜，泛“战斗”不直接推出近身战斗，普通接缝不证明拼接布料。
6. 自然语言支持明确的合理同义表达，但新增召回须经过全文审核、影响扫描和历史反例回放；未经验证的同义扩展不能当成确定归属。

## 4. 父主题与细分的约束

- 每个小主题和细分有稳定名称/ID、明确语义边界及规范父级；同义表达归同一个概念。同名多父级冲突应报告，不用多数票猜父级。
- 一条记录可以跨多个有证据的父主题，但细分必须依附自身正确父主题，不绕过父级门槛强挂细分。
- 发现“原文明明支持细分，但父主题漏了”，先确认并修正父归属，再由细分规则识别。
- **未命中细分不等于父类错误。** 父类范围可能比当前细分词表宽；例如真实浆果仍可支持植物父类，即使没有专门浆果细分。
- 同一原文明确并列多个姿态或风格时，保留各自证据，不由审核者强制二选一。例如 stands 与 half-squatting 同文，不能为了减少冲突就删除站姿；矛盾原文不由分类迁移擅自重写。
- 删除父归属必须确认触发依据是误义、修饰、比喻、否定等，而且没有独立正向证据。真实落地灯、真实尾巴、整理头发等正例不能被同段的错误线索一起删掉。
- 已持久化的父归属通过有备份的离线修正发布。运行时细分计算不自动删除已存父类，也不因浏览或搜索触发重分类。
- 当前审核归属容量跟随注册表，已解除早期 20/40 项硬截断问题。**容量允许不等于可以多挂；每项仍须原文支持。** 历史批量脚本不是重新跑整库的依据。
- 用户明确确认的分类不进入本轮自动批量迁移，冲突保留证据单列。

## 5. 昨晚至今天统一的语义边界

| 边界 | 当前判断 | 必须保留的正例 |
| --- | --- | --- |
| 专名与普通概念 | `project moon`、`the king of fighters`、`tree of savior` 等不能拆词推出月亮、王室、树木 | 独立的 `moon`、`king`、`tree` |
| 服装与整体风格 | 哥特裙、复古眼镜/家具不单独证明整幅画的艺术流派；`idol polish` 不证明偶像职业 | 独立风格词、明确胶片美学、明确职业身份 |
| 制服与设施 | `school uniform/blazer/emblem` 不证明学校建筑；`racing suit`、`mobile suit` 不证明商务西装 | 真实校园/建筑、真实商务西装；制服身份分别有据收录 |
| 饰物与身体 | `neck ribbon/strap` 不证明独立颈部描写；`knee boots` 不证明独立腿部主题 | `bare shoulder`、真实手部/颈部描写；保留裸肩单数别名 |
| 装饰耳与非人特征 | 明确 `fake animal ears` 或明确兽耳 cosplay，耳朵按装饰理解，不以此推真实拟人/生理特征 | 同文独立真实尾巴、角、翅膀继续支持非人父类 |
| 动物与拟人 | `horse girl/boy` 不证明存在独立马匹；`furry hemline` 不证明兽人 | 独立动物、真正拟人主体分别归属 |
| 植物与装饰 | 花纹、纹身、杯上玫瑰、发髻饰花、像素花丝图案不证明独立植物 | 同文真实树木、花束、绿植、浆果保留；不连带删植物父类 |
| 食物与同形词 | `cherry blossom/trees`、`champagne gold`、`tea set/room` 不证明水果或饮品 | 真正水果、饮品、进食上下文 |
| 首饰与环形物 | 能量环、灯环、污渍环、游泳圈不是戒指；酒吧杯子列表里的 `glasses` 不是眼镜 | 手指戒指、实际眼镜、独立臂甲/配饰 |
| 衣物底色与背景 | 和服的 `black background` 是布料底色；有具体环境的暗背景不自动变成纯色背景 | 明确画面纯色/抽象背景 |
| 场景与类比 | “仿佛街拍/游乐园”不证明真实城市场景；图片、招牌、屏幕或包上描绘的环境不等于实际环境 | 正文明确的实际街道、场馆、室内外环境 |
| 阅读角与咖啡馆类比 | `reading nook` 是空间表述，不证明人物阅读；“仿佛在咖啡馆拍摄”不证明真实咖啡馆 | 人物明确阅读、真实咖啡馆场景 |
| 泛户外与自然场景 | 泛 `outdoors` 的历史广义户外口径保留；有明确城市、厨房、舞台、鱼缸等冲突语境时再判断 | 真实泳池/水域、海滩、山地等不误删 |
| 发光与受光 | 皮肤、头发、布料在照明下泛光不等于自发光主体 | 灯具、霓虹、发光眼睛或明确发光标记 |
| 光线动词与身体穿孔 | `sunlight piercing through clouds` 的 `piercing` 指光线穿透，不证明身体改造 | 明确鼻穿孔等真实身体穿孔；真实 LED 发光 |
| 光影与摄影 | 明暗、体积光、电影氛围不一概推出摄影；明确 chibi 语境里仅有 cinematic 不足以补摄影写实 | 明确摄影、写实媒介或具体拍摄美学证据 |
| 实际设备与拍摄方式 | `phone capture/status bar` 不证明画面实体手机；`subway tile` 是砖面，不是地铁 | 手持手机、实际列车等 |
| 人物动作与物体状态 | 布料贴合不等于拥抱；桌子/花瓶“盛放”不等于人物持物；物体或昆虫运动不等于人物运动 | 人物持物、牵手、拥抱或明确人物动作 |
| 穿脱动作与家具 | `dressing room/table/mirror` 不等于穿衣动作 | 同文 fixing/adjusting hair 等真实整理动作保留父类 |
| 人物关系与镜头 | “从背后拥抱/抓住”是人物相对位置，不自动推出背面镜头 | 独立视角说明、明确拍摄角度 |
| 局部、颜色与全裸 | 裸色指甲/唇色不是全裸；局部裸露不自动推出全身裸露；仍穿裙子的 nude form 须结合全句 | 明确全裸与明确局部裸露分别收录 |
| 媒介与画中画 | 泛称“这幅画”、墙上的画、贴纸卡通不自动证明整幅作品媒介 | 明确整体绘画、卡通、摄影等媒介描述 |

成人内容也依完整原文区分动作、道具、状态及主体关系；不因出现一个身体或道具词就推出行为。年龄风险或已排除样本不做定向检索增强，保留排除记录，不换样本凑通过。

心形瞳孔既接受明确的 `heart-shaped pupils` / `heart pupils`，也接受经全文确认确实描述眼睛的 `heart in eye` / `heart in eyes`；仍依附 `眼睛与瞳色` 父主题。后一组写法的扩召回须守住校泳装及其他年龄风险边界，不能因为出现孤立的 `heart` 就推成瞳孔。

这张表是可复用的判定原则，不是只对列举的字符串生效的白名单。实际规则是否扩大或收窄，必须有对照样本与影响审核。

## 6. 小主题和细分的增改标准

- 优先修复正确归属、同义词和现有节点边界，再考虑增类。
- 新小主题应代表稳定、同质、可独立理解的概念，有唯一规范父级；不为单条长提示词、一个偶然修饰、姓名或组合创建碎小桶。
- 新细分必须真的是父主题的一种/一个合理细分维度，命中记录属于父主题，且能被用户理解和筛选。
- 当前已上线的默认显示门槛仍为全局至少 10 个不同记录 ID；每个默认可见细分至少有 3 个不同 ID 的已读全文有效正例。**这是当前实现状态，不是新增叶子的充分条件。** 新增与粒度治理优先服从下方收敛规则。
- 不能扩大语义凑到 10 条，也不能用程序命中冒充 3 条人工正例。规则修正后不足门槛时，需核查漏召回和正例损失；当前界面退出默认显示，稳定 ID 和有效记录保留，不能把退出显示本身当作治理成功。
- 低频概念可留在正确父级，通过原文搜索找到；不必新建“其他细分”。组合筛选后的局部数量不足 10，不代表新出现了错误微桶。
- 作品角色、原创人物、画师标签/组合及综合人物/环境场景，不为填满三级结构逐姓名、逐组合硬拆。
- 提升为大主题必须同时有独立语义轴、足够体量及清楚的交互价值；外部分类表只是参考，不能直接导入全部链接或复合名。

### 6.1 叶子粒度收敛（2026-09-21 用户纠偏，当日起执行）

- **暂停新增叶子和向第四级继续细分。** 当前 500 个可见细分不是数量目标；本轮优先归并重复概念、补齐已有概念召回和修复错归属。
- **小主题自身是完整筛选入口，不要求每条内容落到叶子。** 无适合细分时留在正确父主题，不为追求叶子覆盖率建“其他”或组合碎类；交叉细分不是互斥分桶，父计数不能用子计数相加或相减。
- **准确性修正与概念粒度分开审查。** 排除作品名、比喻等误义不等于缩小概念定义；不得为少量反例给整个概念不断附加苛刻条件。正例误删和漏召回同样属于失败。
- 优先审查全局少于 30 条的细分，30–99 条列入观察，同时看占父主题比例、实际筛选价值及同义重叠。30/100 是诊断分段，不是新的运行时门槛，不能按数值直接删节点。
- 低频项先判定是漏召回、同义重复还是真实低频：漏召回补已有概念，同义重复归并，真实低频且缺乏独立筛选价值者留父主题与原文搜索。不得把不同概念硬合并凑数。合并需保留稳定 ID 的迁移/取消筛选路径并验证。
- 对有保留价值的长尾，后续展示优先“常用细分＋更多”渐进展开，不为整理界面增加分类层级；目前尚未实施该展示调整，不将折叠当成语义合并。
- 每批发布检查新增/移除/改名/改父节点、叶子规模分布及显著缩水。第十九批预检已接入粒度检查：冻结期间注册结构变化阻止发布；单叶净减至少 10 条且降幅至少 30% 时，须留下绑定当前代码/索引哈希的原因、正反例证据，再执行发布。这是额外检查触发线，不是允许其余正例损失。
- 第十九批 .23 粒度及正式接口验收已通过，证据见 `2026-09-21_consecutive_role_scene/granularity_verification.json`、`live_verification.json`。可见细分仍为 500 个，17 个不足 30 条、65 个不足 100 条（.22 为 64 个；车站从 101 条变为 98 条）。注册结构未变、无显著缩水项不等于所有叶子数量未减少。已复读低频概念 51 条记录，未实施合并、隐藏或改变显示门槛，不宣称粒度及全量召回问题已全部解决。原 .22 诊断保留作历史对照。

## 7. 筛选池交互标准

- 点小主题名称：筛选整个小主题。点箭头：展开/收起细分。右键和键盘左右键作为同义入口。
- 展开、折叠本身不改变筛选条件，不触发列表请求；点细分才改变筛选。
- 选细分后显示“大主题 / 小主题 / 细分”路径；它替换该分支显式父条件。“回到父类”清掉该父类细分、恢复父范围，其他分支条件保留。
- 同一个父小主题下的多个细分支持“任一”或“全部”；不同父小主题的细分取交集，即使它们属于同一个大主题。
- 人数、来源、查询、收藏、用途和形式等与语义主题组合；候选数字跟随当前其他条件。
- 动态候选数表示在其他条件下该项能匹配的记录数，不等于点选后 OR 联合结果的总数。父计数不是简单相加子计数；同一 ID 去重。
- 当前为 0 的未选项可以置灰；已选项仍可取消，展开、回父不能被零结果锁死。
- “搜索筛选池”匹配中文名称、完整路径、英文原始 tags，兼容大小写与下划线/空格；自动展开命中路径，已选路径一直可见，清除搜索恢复原展开状态。
- 全局显示门槛不随局部筛选计数变化。页面总数、候选数、分页、卡片归属和服务端实际过滤结果必须一致。

## 8. 连续抽检与验收

主抽检每轮 16 条：1–120、121–350、351–900、901–1800 字符四层各 4 条，至少 8 个来源。先固定种子、样本 ID、正文哈希、目标父类和目标细分；全文阅读，不靠摘要或截断片段判断。

- 每条主目标是预先抽定的父主题/细分关系，同时记录全文中其他明确归属错误；不宣称穷尽每条的一切可选语义。
- 不替换问题样本，不重复旧 ID/相同正文来凑独立新轮。发现问题或排除项，该轮不通过，连续计数归零。
- 修复后的同样本回放、规则影响审核、定向边界样本与补足正例，都不计独立新轮。

## 正交维度必须并出（2026-09-25 确立）

**原则**：一个短语若同时断言两个**正交**事实，必须产出两个节点，不得二选一。

正交维度对（当前已确认）：

- 衣物身份 ↔ 穿着状态（`jacket` ↔ `wear_state.open`）
- 发长 ↔ 发色 ↔ 发质（`hair.long` ↔ `hair.black` ↔ `hair.curly`）
- 身体部位 ↔ 暴露遮盖（`part.shoulder` ↔ `cover.shoulders`）
- 姿势 ↔ 运动（`sit.sitting` ↔ `motion.*`）

**判定依据**：本库的用途是检索。用户按「夹克」检索时不应因夹克敞开而漏掉；按「敞开衣物」检索时不应漏掉敞开的夹克。丢掉任一维度都只损失召回，换不来精度。

**反例（已修正）**：引擎原先在一段匹配被接受后直接跳过整个跨度（`i = finish + 1`），导致更长的标签吞掉其内部更短的标签——`open jacket` 隐藏 `jacket`、`long black hair` 隐藏 `black hair`。2026-09-25 改为逐词推进（`i = i + 1`），实测全库 +1,700 余个叶子、**零丢失**、父类与 theme 计数零漂移。

**待办**：`open <衣物>` 与 `long <色> hair` 的复合标签仍受一处既有守卫压制（`open shirt` 从出厂起只出状态、不出衣物），需与 `open shirt` 一并校正，属匹配内核专项，不得作为标签批次处理。
