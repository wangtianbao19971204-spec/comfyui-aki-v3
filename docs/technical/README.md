# 技术接手总入口

这里按功能查找唯一实现、资料边界、测试、示例和更新记录。先选一项功能，再沿链接深读。

快速了解结构见[项目地图](../PROJECT_MAP.md)与[快照说明](../SNAPSHOT.md)；操作入口见[文档导航](../README.md)，新增自述按[文档维护规则](../DOCUMENTATION.md)。

## 如何修改一项功能

[历史技术原件](archive/README.md)按原目录保留，完整[来源/角色/SHA 登记](../../governance/technical-archive.json)可供机器验证。现行维护入口由对应功能说明和目录登记确定。

先读对应 L2 技术说明与当前 Git 状态，再改其唯一源码。正常部署源码在 `snapshot/runtime/`；结构/迁移在 `database/`，项目治理工具在 `scripts/`。历史维护实现放 `docs/technical/archive/` 时只作可追溯参考，不能把写死日期、PID 或路径的旧发布脚本当日常命令。复用前先提炼到受测、参数化的新维护入口。

每次代码改动同时补该功能 MD 的日期式更新记录，或新增 `docs/technical/changes/<feature-id>/<日期>-<简述>.md`。记录“改了什么、为什么、验证什么、未验证什么、回滚依赖”，无需长篇重复源码。新增功能同时登记 `catalog.json`，不能只补一条总 CHANGELOG。

```powershell
python -X utf8 -B scripts/technical_catalog.py check
python -X utf8 -B scripts/technical_catalog.py check --staged --enforce-changes
```

检查实现/测试/证据/示例文件和可移植相对链接，并根据最具体的源码归属要求对应说明随提交更新。19 项功能各有非空 `examples` 清单：可以是现行操作说明、真实工作流模板、隔离测试样例或明确标为虚构的格式/标注文件，不能以路径引用冒充真实媒体或功能实测。缺文件、未跟踪或仅在工作树补齐而未进入暂存区的示例不能通过相应门禁。

源码以外的 `governance/`、`examples/`、`snapshot/library/` 和 `snapshot/inventory/` 更新同样需要对应技术记录；这不授权手工改库分片或覆盖在线数据。它不自动验证 UI、语义准确率或 GPU 画质；功能实测仍是独立门禁。

## 唯一来源与资料边界

本地实际环境是主 Git 部署文件，加上仓外私密配置、模型/预览、依赖环境和应用最新数据。所谓“私有仓”当前是普通本地资料区，不是第二个开发 Git，也没有自动加密、同步或异地灾备保证。旧原 Git、历史候选和回滚原件是私有档案，不参与日常开发。

已移入 Git 的代码不等于其全部输入都随 Git 保存。目录引用不是备份；数据库导出是检查点，不能覆盖更新的在线库。真实源网页、Word、逐轮评分、训练图片、权重及大缓存可以只保留原件并登记位置；Git 提供格式/放置样例及必要技术说明。详见 [外部资料](../EXTERNAL_STATE.md)、[资源样例](../EXTERNAL_ASSETS.md)。

技术代码许可与源资料、图片的再分发权利分开核对。凭证门禁通过不是版权授权，也不是新机器可以立即运行的证明。
