# LoRA 预览获取与上传

更新日期：2026-10-07。

顶部“获取”用于补齐来源资料和缺失预览。“刷新”重新读取本地模型列表；单卡“替换预览”用于选择自己的图片。已有本地预览不会被顶部“获取”覆盖。

## 修复内容

旧批量获取只选择没有 Civitai 版本 ID 的模型。导入器已登记来源后，缺图项也被跳过；本次让它们进入独立补图流程。优先使用侧车里已有的图片候选，必要时按完整 SHA 查询来源，只取图片，不覆盖规范名称、触发词、收藏、备注及其他个人字段。跳过设置、外部来源、已确认删除及限流保护仍有效。

侧车已有图而列表缓存缺图时，只修复缓存。下载、侧车保存或缓存更新失败会进入失败清单，不能计为成功；后续重试保留已经落地的图片。

手动上传和从网址设置预览显示后台的具体失败原因，并检查返回值。图片保存成功后更新卡片与缓存版本；卡片已离开当前列表时从第一页重载。重载途中切换页面或重建列表，会丢弃旧响应，避免把 LoRA 列表写进另一种模型页面。

预览保存链保留旧图直到新图、侧车和缓存均保存成功。手动图片与 GIF 在落盘前校验真实解码，远端图片和优化输出也校验；拒绝损坏图片和冒充图片的 HTML，避免旧转换工具退回原字节却报告成功。远端文件后缀受预览格式约束，不能作为模型权重或侧车的输出路径。图片、真实侧车与缓存不进入 Git。

## 实现与验证

唯一实现位于 [LoRA Manager](../../../../snapshot/runtime/ComfyUI/custom_nodes/ComfyUI-Unified-Prompt-Workbench/modules/comfyui-lora-manager/) 的 `py/services/{metadata_sync_service,preview_asset_service}.py`、`py/services/use_cases/bulk_metadata_refresh_use_case.py` 和 `static/js/api/baseModelApi.js`。相关测试在同模块 `tests/services/`、`tests/routes/` 及新增 `tests/frontend/api/baseModelApi.preview.test.js`。前端测试配置把统一包的公开扩展路径映射到仓内源码，便于独立运行。

相关后端组合回归 111 项通过，前端六文件共 40 项通过，主仓维护回归 584 项通过。覆盖缺图入队、已有图保持、个人字段、失败计数、缓存恢复、安全保存、PNG 转 WebP、GIF 保帧、无效图片拒绝、错误展示及页面切换。原版本另经九个中文目标名称、两种路径分隔符共 18 例真实上传验证；生产页面诊断请求已截获，未发送到生产上传接口。

候选源码另经浏览器隔离上传验收：实际前端 API 客户端、实际上传 handler、Pillow 与 MetadataManager 连通，合法图片返回成功并显示为 480×320 的预览；再次选择无效图片返回失败，原预览与侧车摘要均保持，模型字节、个人字段及侧车／缓存一致。页面状态、卡片和 scanner 使用隔离替身，本轮不等于完整生产页面、真实在线持久缓存或外网取图验收。脱敏结果见[验收收据](../../../receipts/lora_preview_binding_20261007.json)。

顶部“获取”跳过缺图项的代码条件已证实。用户报告的手动选图后没有变化，尚未在其原页面复现；本次修复已确认的错误隐藏、保存失败假成功及卡片刷新边界，不能宣称已证明那一次操作的唯一原因。

## 部署与回退

当前为主仓修复，未部署运行区。部署范围仅上述四个源码文件；测试文件、文档与测试配置不部署。三个 Python 文件需要服务重启才会生效，前端文件需要刷新管理页。部署前按主仓规则记录实时服务与队列、保存源码回退副本和数据库一致备份，取得明确部署授权后才操作运行实例。回退恢复四个原文件及匹配服务，不用旧数据库覆盖最新用户数据。
