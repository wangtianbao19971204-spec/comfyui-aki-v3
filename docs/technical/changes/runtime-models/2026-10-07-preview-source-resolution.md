# 预览来源查询补正

更新日期：2026-10-07。

顶部“获取”已经会处理已有来源但缺图的模型。生产重试扫描 292 项，其中九项报 `Model not found`，其余 283 项保持跳过。本次修复这九项在查询来源时的失败。

## 已确认的原因

九个侧车的版本 ID、模型 ID 和实际完整 SHA256 均与导入登记及上游声明一致；侧车没有保存图片候选，所以补图需要查询远端。九个官方版本接口均返回 200，精确版本／模型／登记文件及摘要全部匹配，共有 62 个图片候选。

客户端原来固定使用 `civitai.red`。同一 GYARI 版本在官方接口按版本、按 SHA 查询都返回正确资料，而镜像两种请求均连接失败。现行回退链耗尽非限流失败后统一返回 `Model not found`，因此生产报告不能用来判定模型被删除。旧缺图路径只按 SHA 查询，没有利用已经登记的版本 ID。

## 当前改动

- 客户端恢复官方 `https://civitai.com/api/v1`，继续使用原下载器的认证、限流及离线机制；旧镜像来源网址仍可按图片 ID 解析，不自动增加镜像重试。
- 有本地预览时只修复列表缓存；有侧车图片候选时直接使用。其余已关联项优先查询精确版本，确认返回的版本／模型身份；已有完整本机 SHA 时，还需有匹配的远端文件。身份不符时不下载、不写侧车或缓存。
- 没有版本 ID 的记录保留按完整 SHA 查询。来源失败保留版本查询返回的错误和限流结果，不重新按 SHA 扩大请求；补图只采用图片，规范名称、触发词、备注、收藏及其他个人字段保持。
- 缺失、空或没有可用 URL 的版本图片响应不长期命中缓存，后续“获取”会重新查询；有图响应继续使用原来的 500 项 LRU 缓存。

唯一源码在 [LoRA Manager](../../../../snapshot/runtime/ComfyUI/custom_nodes/ComfyUI-Unified-Prompt-Workbench/modules/comfyui-lora-manager/) 的 `py/services/civitai_client.py` 和 `py/services/metadata_sync_service.py`，测试在同模块 `tests/services/`、`tests/routes/` 与 `tests/utils/`。
