# 本地快照增量检查

日期：2026-10-11。

小改动此前仍会让 seal 重读全部源码、资料分片和重复运行内容检查。现在本地主仓的 status、seal、deploy-plan 默认复用成功验证后的文件和目录指纹。上传的全历史缓存是另一层，继续按其原有规则工作。

- 每次仍枚举文件名及文件元数据，检查新增、删除、改名、链接、越界、禁入路径、清单及顺序。目录指纹由后代文件的相对名称与身份组成，不能只用目录 mtime。
- 文件身份包含设备／inode、长度、mtime、权限、链接数和变更时间。Windows NTFS/ReFS 读取真正的 ChangeTime，不能使用 Python 的 Windows creation-time 代替；同大小、恢复 mtime 的覆盖仍重新读内容。不可靠元数据不缓存。
- 命中后跳过完整内容读取、SHA-256 和基础凭证模式扫描；变动项重新执行。分片摘要全部核对后，只有路径、顺序、实际摘要及预期拼接摘要都一致，才复用上次拼接验证。
- 缓存位于本工作树 Git 管理目录，绑定根路径、目录身份、Python 版本和检查器代码。只在全部验证通过且文件／规则未漂移后原子保存。损坏、规则变化、另一克隆或新环境不继承旧结果。容量受限，文件正文不入缓存。
- `project.py ... --fresh`、不带 `--incremental` 的 `snapshot.py verify`，以及 CI、capture、restore、bundle、release 的默认 API 仍完整读取。缓存是可信本机的性能优化，不是抵御有权限篡改缓存／系统元数据者的安全证明。
- `deploy-plan --scope <运行相对路径>` 支持多个文件／目录，只读取所选运行文件；源快照仍完整枚举。生成只读计划，不执行覆盖，不替换数据库。模型、LoRA 和预览继续仓外维护。
