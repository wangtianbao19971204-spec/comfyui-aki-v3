# 2026-10-11：原版 Anima 控制实机验收与限定部署

a1 简化控制的候选源码此前只有 CPU、界面与导出重载证据。本轮在实际 GPU 上用固定提示词和种子出图，核对控制是否真的约束画面，再把同一批源码部署到正式工作流。

## 出图矩阵

隔离实例从本仓 `snapshot/runtime` 复制，独立端口与独立数据库，模型只被引用。提示词为固定中性句，种子 845401323336067，28 步，CFG 3.5，Euler/sgm_uniform，LoRA 栈为空，控制强度保持生产默认 1，预处理分辨率 1024。七例：关闭控制、PyraCanny、HED、Manga2Anime 线稿、DepthAnythingV2、擦线、VNCCS 姿势。

提交仍走[本地验收工具](../../../../scripts/native_workflow_acceptance.py)，只按正规 API 图执行、逐例新证据目录、只在空队列时提交。图由真正的前端（无头 Chrome）产出：常用控制台应用每一例，`Export (API)` 导出图，提交时把控制图预览与擦线预览作为部分执行目标，因此采样器不参与，控制链保真度来自已部署前端而不是本仓的再实现。

## 结果

- 六例同尺寸输出（1040×1520）：相对无控制基线，平均绝对差 37.6–46.5，变化像素 88.2%–95.1%，四种预处理和擦线都显著改变画面；画面上人物、手与自行车的位置与朝向跟随参考图，控制确实在约束采样。
- 控制图（1024×1498）四例互不相同：细致线稿、柔和线稿、漫画线稿、深度图各自呈现对应结构。控制分支真正消费的参考图由“用已部署 AIO 对候选输入逐一复算并与前端控制图比对”确定，仅 `06693d11` 一项吻合（平均绝对差 3.3，其余 43.7–60.2）。
- 擦线：`LoadImage` 把单通道图暴露为 `1 - 值`，因此白色矩形才是被擦区域。用带 alpha 的确定性遮罩后，控制图在 `[90,731,390,1464]` 内改变 37029 个像素、最大差 255，x 范围与遮罩完全一致，擦除内部为黑。第一版 RGB 遮罩被 `LoadImage` 当成全零 64×64 蒙版，那一轮判为未生效并重跑，不作擦线通过。
- VNCCS：真实前端渲染并捕获 832×1216 姿势图，经文档化的同步与缓存接口上传（均 HTTP 200），后端执行日志显示从缓存取用该 capture id，未走 Python 备用渲染。
- 生产路线：同一前端解除姿态子图静音后，用 `Export (API)` 提交一次完整流程，49 节点执行成功，最终保存、控制预览、擦线预览与临时线稿保存都正常产出。

## 部署与核验

范围为四份 a1 工作流／模板。候选由当次运行区原件经[迁移工具](../../../../snapshot/runtime/production_tools/simplify_anima_control.py) `--branch a1` 生成，逐项核对根节点模式、参数、其余子图和不相关字段；候选与 `snapshot/runtime` 原件逐字节相同。空队列时备份四文件与一致 `comfyui.db` 副本，停旧进程，替换文件，用原命令行与 `AKI_HUISHI_PROFILE=production` 重启。重启后四文件 SHA256 与清单一致，姿态子图 9 节点、VNCCS 子图 6 节点、擦线高级子图 8 节点，注册缺失为零，四个控制属主仍为默认静音，队列为空。

回归：`test_anima_control_workflow.py` 8 项、`test_vnccs_pose_sync.py` 2 项、以及 `test_anima_control.cjs`、`test_uap_daily_controls.cjs`、`test_uap_navigation.cjs`、`test_uap_compact_widgets.cjs`、`test_vnccs_pose_sync.cjs` 全部通过。

## 限制与现场事实

- 本流强度仍是生产默认 1。该强度下控制明显过约束：姿态跟随参考图，但脸与四肢退化。强度属于用户参数，本轮不改默认值，也不认证任何强度的成图质量。
- 两种子图在保存文件里默认 `mode=2`；要执行控制必须先启用分支。工作台擦线开关本身只切换高级子图的模式。
- 已保存的擦线遮罩是 RGB，`LoadImage` 取不到 alpha，因此即使高级子图启用，该遮罩的合成为空操作；要真正擦线，遮罩需带 alpha。
- VNCCS 无浏览器的 Python 备用渲染、SAM3D 图片提取与精细姿态编辑忠实度仍未认证。
- 未下载模型、未替换在线数据库、未合并 PR。
