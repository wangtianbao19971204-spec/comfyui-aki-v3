# 2026-10-11：Krea2 接入 VNCCS 姿势深度来源

Krea2（k2）分支原本就有一条完整的深度控制链，但 VNCCS 姿势工作室的输出只接了预览和前后对比，没有进入模型。本轮按线稿来源选择 `1157` 的既有形态，给深度来源也加一个同形状的选择器。

## 现状与问题

k2 是平铺结构（96 个根节点，没有子图），深度控制链为：

```
1190 参考图 → 1153 缩放 → 1191 DepthAnythingV2 → 1159 Krea2ControlImageEncode
           → 1161 Krea2ControlApply ← 1160 Krea2Depth ControlNet-LoRA ← 1173 LoRA 栈
1172 VNCCS_PoseStudio → 1228 预览 / 1150 前后对比        （不参与执行）
```

也就是说 Krea2 的"姿态参考"此前只是展示：姿势渲染图没有任何下游控制消费者。

## 改法（对齐既有模式）

新增三个根节点，全部并入 k2 分支与 `CORE-05 参考预处理与控制图生成 · K2 Krea2` 分组：

| 节点 | 类型 | 作用 |
|---|---|---|
| `130160` | `DazzleSwitch` | `[05B6] Depth 来源选择（参考图 / VNCCS 姿势）` |
| `130161` | `DepthAnythingV2Preprocessor` | `[05B4P] VNCCS 姿势深度`（1172 → 深度图） |
| `130162` | `PreviewImage` | `[05V4] VNCCS 姿势深度预览` |

接线：`1191 → 130160.input_01`、`130161 → 130160.input_02`、`130160.output → 1159.control_image`（原 1191 → 1159 的连线改接），`1172 → 130161`、`130161 → 130162`。形状与 `1157`（线稿来源选择）和既有 `05V*` 预览一致。

`select=(none)` + `mode=priority` 时 `DazzleSwitch` 取第一个非空输入，即 `input_01` = 原参考图深度，**默认渲染结果不变**；把下拉切到 `input_02` 即改用姿势深度。

## 验证（隔离实例，真实前端）

- 结构：根节点 294、根连线 390，所有输入端口都能解析到存在的连线，子图边界端口除外零异常；编码器 `control_image` 现在来自 `130160`。
- 前端：候选页激活 k2 分支（99 节点、96 个解除静音），两条输入均已连接。
- 分档 A/B（单浏览器会话、先固定姿势截图，保证两次运行的姿势深度一致，只改开关档位）：两次运行里**姿势深度与参考图深度的像素完全相同（差 0）**，而编码器输出平均绝对差 90.3、最大 220。
- 归属：`select=(none)` 时编码器输出与参考图深度吻合（重采样后平均差 0.94）、与姿势深度差 90.16；切到 `input_02` 后反过来（与姿势深度 0.46、与参考图深度 90.16）。

## 限制与未做

- 只验证到"控制图来源被正确切换并进入编码器"，**没有跑完整 Krea2 采样**，因此不认证姿势控制在成图上的效果或质量；网格渲染图不是自然场景深度，效果需另做实跑对比。
- 未部署到运行区：本轮只改主仓源码与模板，运行区仍是改动前的工作流，等合并后再按范围部署。
- 文件里同类连线使用数组编码 `[id, origin, slot, target, slot, type]`；首次写入用了字典编码，前端 `graphToPrompt` 报 `InvalidLinkError`，已改为与文件一致的数组编码并复验。
- 未改任何既有节点参数、提示词、种子、LoRA 或默认开关。
