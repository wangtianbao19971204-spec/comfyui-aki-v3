# 2026-10-11：K2 线稿与控制链子图化（真正生效）

用户要求"擦除逻辑一致、可切换、确实生效、子图化、根目录简洁"，三条工作流都要这样。Anima 两个分支原本就以 `[05] 线稿与姿态控制` 子图承载这条链，缺的是 K2。本轮把 K2 的整条链做成子图。

## 之前失败的真正原因（记录以免重犯）

两次尝试都失败，我一度判定"前端不支持"，实际是两个可避免的问题：

1. **选区不完整**。若子图内部还有节点需要从子图外取输入，前端解析不了"父图→子图内部节点"的连线，`graphToPrompt` 抛 `InvalidLinkError: No link found in parent graph for id [<实例>:<内部节点>]`。把姿势分支与编码器一并选进子图后，这个方向不再存在。
2. **手工写的定义缺前端内部状态**。前端的 `Convert to Subgraph` 会在定义里写入它自己需要的映射（端口 `linkIds` 与实例的 `previewExposures` 等）。手写 JSON 结构再对称也补不齐，实例输出解析不出来。

用**前端自身的转换器 + 完整选区**，两条都解决：导出直接给出 `control_apply.control_latent = ["<实例>:1159", 0]`。

## 做法

在运行区前端里（`local/ui_convert_k2.py`，经 `Convert to Subgraph` 等价路径）：

- 选区：`1153 参考图缩放、1141/1142/1143 预处理、1191 参考图深度、1157 线稿来源选择、1140/1144/1145/1146/1147/1152/1155/1164 擦除链与预览、1167/1168/1169/1189 预处理预览、130161 姿势深度、130162 姿势深度预览、130160 深度来源选择、1159 控制图编码、1162 控制图预览`；
- 生成定义 `K2 线稿与控制图`（23 节点），实例 `130163`；
- 端口重命名为可读名：输入 `image / lineart / vae / latent`，输出 `pose_compare / lineart_preview / control_latent`；
- 同步 k2 分支元数据：`nodeIds` 去掉被打包的 23 个节点、加入实例，`modes` 同步（77 节点）；
- 落地到正式工作流与权威模板（根节点 294→272）。

## 三条工作流的一致性

| 分支 | 控制链载体 | 线稿来源选择 | 擦除实现 | 遮罩 |
|---|---|---|---|---|
| a1 Anima 原版 | `[05] 线稿与姿态控制` 子图 | 子图内 `控制方式` | 子图内 `高级 · 擦线与导出` | `clipspace-painted-masked-…png` |
| a29 Anima 2.9B | 同上 | 同上 | 同上 | 同上 |
| k2 Krea2 | `K2 线稿与控制图` 子图（新增） | 子图内 `[05B5]` | 子图内 `[05C*]` | 同上 |

三条都是"参考图 → 缩放 → 预处理/线稿来源 → 擦除 → 控制应用"的同一形状，各自持有实现、根级只留一个实例。

## 已知差异（不是缺陷）

- Anima 侧的控制应用是 `AnimaLLLiteApply`（把控制图挂到模型上，输出 MODEL/LATENT 给采样器），Krea2 侧是 `Krea2ControlImageEncode + Krea2ControlApply`（输出 control_latent）。这是两个模型族的控制机制差异，无法统一。
- 子图内部节点在导出后以 `<实例>:<内部节点>` 命名，属前端正常行为。
- 自动暴露的 `image_1`/`upload`（遮罩上传口）未连接，保留不影响运行。

## 限制

- 擦除的**画面级**效果未做"遮罩换值"的 A/B：clipspace 遮罩引用在前端是**节点加载时固定**的（运行时改控件值不会改变导出结果，我实测过）。因此验证改用定义内 `SolidMask` 值探针，证明内部改动确实进入控制链；遮罩文件本身在最小链路测试中已证明差异（RGBA 20.17% 变化 / 无 alpha 0）。
- 打包后原链路的中间预览（HED/Canny/Manga/Depth、擦线前后、控制图）都在子图内部，根级画布上不再直接可见，需要在子图里查看。

## 追加：实例上的遮罩控件处理

子图化后前端会把定义内遮罩加载器的控件"提升"到实例上，于是节点卡上多出一个文件下拉和 `upload` 按钮，但在实例位置既没有图片预览、也没有可上传的目标，属于误导。

处置：

- `upload` 端口两侧一并移除（在实例上它没有作用）；
- 遮罩文件下拉留在**子图内部**——加载器在那里保留原生预览与遮罩编辑器；
- 实例收敛为 4 个接线输入（`image / lineart / vae / latent`）与 3 个输出（`pose_compare / lineart_preview / control_latent`），节点卡上不再出现文件控件。

核验（运行区前端实页）：

| 检查 | 结果 |
|---|---|
| 实例端口 | `image/lineart/vae/latent`，均非控件 |
| 实例控件 | 空（节点卡无下拉、无上传按钮） |
| 子图内加载器 | `image`(combo) + `upload`(button) 保留，值仍为 `clipspace/clipspace-painted-masked-1782566128506.png` |
| 导出解析 | `1161.control_latent = ["130163:1159", 0]`，子图展开 23 个内部节点 |
| 渲染 | `success` → `_codex_qa/krea2_subgraph_live/krea2_00003_.png` |

改遮罩的方式：双击实例进入子图，用 `[05C2] 白色擦线遮罩输入` 的下拉/编辑器，或看 `[05V6] 擦线遮罩预览` 确认范围。
