# 擦线遮罩一键画布：自动读取当前线稿（2026-10-25）

- 问题：`控制与擦线 → 画擦线区域` 直接打开原生 MaskEditor，但遮罩节点 `[05C2]` 是普通 `LoadImage`，需要先在它的下拉里选一个文件；工作流保存的是旧版 MaskEditor 的 `input/clipspace/...` 子目录路径（`LoadImage` 只列出 input 根目录文件），于是预检报「缺少输入 / 所需的媒体输入未选择文件」，用户必须先手动选图才能画遮罩。
- 改动：`web/control_switches.js` 在 Krea2 根级流程里新增 `prepareMaskCanvas()`：点「画擦线区域」时先取 `[05V5] 当前线稿来源预览` 的最近输出；若还没有输出，则临时把该预览节点从静音恢复、用 `queuePrompt(..., {queueNodeIds:[previewId]})` 只跑出线稿预览，随后恢复原 mode。取到线稿图后上传到 `input/`，写入 `[05C2]` 的 `image` 控件，再打开原生 MaskEditor——画布就是当前正在生成的线稿，用户不再需要在下拉里选文件。预览结果缓存在节点的 `imgs` 上，重复点击不重复跑图。Anima 子图/非根级或不满足条件的流程保持原行为。
- 验证：`production_tools/test_control_switches.cjs` 新增 Krea2 用例（预览节点 498、静音恢复、画布上传、mask 控件写入、二次点击复用缓存、不重复排队）；全套 5 个用例通过（12 个工作流 scope + 1200 次擦线往返 + 面板生命周期 + 自动画布）。`node` 运行通过。
- 限制：首次点击若工作流尚未跑过，会先执行一次“当前线稿预览”（会跑所选控制来源的上游预处理，耗时接近一次生成前的预处理阶段；具体取决于所选预处理/模型），完成后面板显示“正在生成当前线稿画布…”；之后复用缓存。Anima 子图流程暂未接管自动画布（仍按原方式打开遮罩编辑器）。
