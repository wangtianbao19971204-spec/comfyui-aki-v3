# 工作台提交回执与待用资料异常保护

## 提交与取消

原生前端 `queuePrompt` 在已有请求正在处理时，会把新请求放入本地提交队列并返回 `false`，之后仍可能提交到服务。运行按钮此前立即把这一返回值显示为“未提交”，可能引导用户重复提交。

`run_controls.js` 现在以本次 `promptQueueing` / `promptQueued` 的 `requestId` 和正数 `batchCount` 作为接受凭据。原生 `nextQueueRequestId` 可用时预先绑定身份；旧接口保留首个 queueing 的兼容路径。返回 `false` 但本次已进入原生处理队列时，按钮保持忙碌并等待本次回执。50 ms 检查仅用于观察处理状态与当前工作流，不能凭等待时间判定成功。

工作流对象、图 ID、节点数组或 UAP 活跃分支改变后，停止等待并提示用户到队列核对旧请求。它不会把未知状态宣称为未提交，也不会自动中断已经交给后端的任务。销毁控件会立即解绑临时回执监听和计时器。原生契约参照本机已安装前端的 `settingStore-CwkLtSKP.js`；真实页面提交、后端队列和部署由本轮实机验收另行记录。

## 待用资料

缓存恢复改为逐条校验，坏记录不会连带丢弃有效邻项。非网页项检查稳定身份、正文、权重、用途和未完成拆分的字段类型；网页项仍使用原有来源、UUID、方向与原文校验。空的未完成编辑允许保留，但不能应用。无效 JSON、缓存容器错误或读取失败有明确提示；会话保存失败时保留当前内存和可编辑页面，不误报已持久保存。

原资料复核必须全部读取成功且正文、用途均为字符串，之后才能更新草稿。一个资料返回异常时，同批中有效资料的刷新也不会先写入缓存。原资料连续改变时，每一轮都先更新预览并停止应用，直到下一次稳定复核；临时正文和手动拆分继续保留。使用记录遇到版本冲突最多重试三次，记录失败不会重复插入正文。

待用面板增加宿主 DOM 与界面版本检查。关闭、重新挂载或切换目标后，旧复核不能更新共享草稿、缓存或写入目标。`prompt_target.js` 的共享写入器支持可选 `request.validateCurrent`，在原有异步微任务之后、读取或提交之前复核调用方生命周期。待用列表传入该守卫，并绑定准备时的草稿版本，覆盖“读取已结束，但写入尚未执行”的窗口。其他调用方未传此字段时保持原行为；预览、动作列表和撤销仍委托原共享写入器。
